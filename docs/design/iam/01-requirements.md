## 1. 背景

SecPlexus 是跨厂商告警之上的 AI 分析师层。一家公司内部往往有多个部门（安全部、运维部、各业务线 SOC 小组），各自接入各自的告警源、各自研判各自的案件——**部门之间的数据不能互看**（例如 A 部门的研判结论、机构记忆、实体档案，B 部门不可见），但全公司共享同一份威胁情报。

同时，SecPlexus 的用户量级很小（单部署几十到几百人），不需要大厂式的"用户中心 / 权限中心 / 认证中心"分离建设——那是在几十个系统、几万员工规模下的部署妥协。我们需要的是**一个完整的、内建的、符合行业标准的身份与权限体系**，作为全平台唯一的权威源。

iam（Identity and Access Management，身份与访问管理）就是承载这一切的服务：**认证（你是谁）、目录（组织与用户）、授权（你能干什么）、上下文分发（把身份与组织上下文可信地交给每个请求）**——四合一，全部收敛于此，任何其他服务不实现自己的用户/权限逻辑。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 | 衡量 |
|---|---|---|
| G1 | 全平台唯一身份权威：一次登录访问所有功能 | 无第二套账号体系 |
| G2 | 部门级数据隔离：A 组织看不到 B 组织的告警/案件/记忆/实体档案 | 隔离测试 100% 通过（见 §10） |
| G3 | 权限到菜单：改一个角色的权限，该角色用户的前端菜单即时变化 | 无前端发版 |
| G4 | 管理自助：组织/用户/角色的增删改全部在页面完成，不需要改配置文件或重启 | 管理操作全程界面化 |
| G5 | 后来者不改错：新开发者新增 API/表/菜单时，隔离与权限由框架自动保证 | 接入 SOP 每项 ≤ 4 步（技术设计 §14） |
| G6 | 可插拔企业 IdP：用户已有飞书/钉钉/AD/Keycloak 时，标准协议接入，不迁移账号 | OIDC/SAML 对接零定制 |

### 2.2 非目标（v1 明确不做，但架构预留）

| # | 不做 | 为什么 / 预留方式 |
|---|---|---|
| N1 | 不做社交登录（微信/GitHub 登录） | 企业内网产品无此场景；OIDC 协议层天然支持未来扩展 |
| N2 | 不做完整的 SCIM 服务端 | v1 手工建用户够用；SCIM 入站同步列为 P1，接口形状已按 SCIM 2.0 设计 |
| N3 | 不做 ABAC 细粒度条件（时段/IP 段放行） | v1 用 RBAC；策略表预留 conditions 字段，演进不迁移 |
| N4 | 不做树形嵌套组织（集团→子公司→部门） | 嵌套继承的可见性规则是复杂度黑洞；平铺 org + 用户组覆盖当前场景，需要时再评估 |
| N5 | 不做密码找回邮件流 | 内网由管理员重置；邮件通道上线后（SOAR 通知）再开自助找回 |
| N6 | 不替代外部 IdP | 我们是"内建 + 标准协议对外"：部署 Zitadel/Keycloak 的用户可把认证整个外包给它（方案 B 升级路径，见技术设计 §14.4） |

> 非目标的共同原则（用户明确要求）：**有些东西现在不做，但架构层面把口子留好，后面加就是顺水推舟，而不是重构。**

## 3. 术语表

| 术语 | 定义 |
|---|---|
| IAM | Identity and Access Management（身份与访问管理）：认证（你是谁）+ 目录（组织与用户）+ 授权（你能做什么）的合并领域。本平台的 iam 是一个代码模块 + 一个角色，不是微服务 |
| 组织（Organization / org） | 数据隔离与授权的基本单位，对应公司内的部门或独立团队；字段 `org_id`。平铺，不嵌套 |
| 用户组（Group） | 组织内的用户分组，用于批量授权；不做数据隔离（隔离只在 org 级） |
| 角色（Role） | 一组权限点的命名集合，用户在每个组织中持有一个角色 |
| 权限点（Permission） | 最小授权单元，命名 `resource:action`（如 `cases:write`）；菜单可见性由权限点派生 |
| 平台管理员 | 跨组织的角色，管理组织本身与全局配置 |
| 会话（Session） | 浏览器登录态，服务端存储、可即时吊销 |
| API Token | 机器/脚本身份的长效凭据，展示一次、哈希存储、可吊销 |
| 机构记忆 | AI 研判结论与人工纠正的经验库，**按组织隔离** |
| 三层可见性 | 全局共享层（情报/规则）/ 组织隔离层（告警/案件/Ledger）/ 组织隔离层（机构记忆/实体档案） |
| PDP / PEP | 策略决策点（iam）/ 策略执行点（API 中间件、数据层 RLS、前端渲染） |

## 4. 用户角色与核心场景

### 4.1 角色（Personas）

| 角色 | 说明 | 典型诉求 |
|---|---|---|
| 平台管理员 | 安全平台负责人，全公司 1–2 人 | 建组织、给组织指定管理员、管全局设置 |
| 组织管理员 | 部门 SOC 负责人 | 管本部门用户与角色，看本部门全部数据 |
| 安全分析师 | 部门一线，研判告警处理案件 | 三队列工作台、深度调查、深度调查中的工具调用 |
| 只读用户 | 合规/审计/领导 | 看板与报表，不能改任何东西 |
| 机器身份 | 脚本/对接系统 | 用 API Token 调 API，权限同用户体系 |

### 4.2 核心用户故事（按价值排序）

1. 作为安全平台负责人，我要创建"安全部""电商线""支付线"三个组织，并给每个组织指定一名组织管理员——这样各部门的数据天然分开。
2. 作为组织管理员，我要在页面上添加用户、分配分析师角色、停用离职人员账号——全程不需要找开发。
3. 作为组织管理员，我要给"只读用户"角色去掉"处置审批"，保存后该角色用户刷新页面就看不到"待审批"菜单——权限变化即时生效。
4. 作为分析师，我登录后只看到本组织的告警、案件和机构记忆；查询任何接口都拿不到别的组织的数据——即使接口被误改，数据库层也兜底。
5. 作为平台管理员，我要为 CI 流水线签发一个 API Token，只给"查询告警"权限，泄漏后能立刻吊销。
6. 作为平台管理员，公司上了飞书统一身份后，我要把登录切到 OIDC 对接飞书，老账号首次登录自动绑定——不需要批量迁移。
7. 作为开发者（内部用户），我要新增一张业务表，只要表带 `org_id` 列，隔离自动生效，不需要写任何过滤代码。

## 5. 功能需求

优先级定义：**P0** = v1 必须，无它不可发布；**P1** = v1.x，发布后尽快；**P2** = 规划中。每条需求附验收标准（AC）。

### 模块 A：认证（Authentication）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| A1 | 账号密码登录：用户名/邮箱 + 密码，签发浏览器会话 | P0 | 正确凭据登录成功；错误凭据返回统一模糊错误（不区分"用户不存在/密码错"） |
| A2 | 密码策略：最小长度 12、复杂度（四类中三类）、禁止常见弱口令（top-1000 列表） | P0 | 违规密码在设置/修改时被拒绝并说明原因 |
| A3 | 登录防爆破：同一账号连续 5 次失败锁定 15 分钟，锁定期间正确密码也拒绝；IP 级限速 | P0 | 第 6 次尝试返回锁定提示；15 分钟后自动解锁；全过程审计 |
| A4 | 多因素认证（TOTP）：用户可自助绑定 TOTP（扫码）；**强制 MFA 按角色配置**（角色的 `mfa_required` 属性，管理员可改；预置 org_admin 及以上默认开） | P0 | 绑定流程含一次性确认码；命中强制角色而未绑定的登录被引导绑定、完成前不签发会话 |
| A5 | SSO（OIDC）：管理员配置 OIDC 提供方（飞书/钉钉/Keycloak/Zitadel），用户跳转登录，首次登录按邮箱自动关联本地账号或自动建号（策略可选） | P0 | 对接任一标准 OIDC 提供方无需写代码；登录后组织归属按配置的默认组织落定 |
| A6 | SAML 2.0 对接 | P1 | 对接标准 IdP（AD FS/Keycloak） |
| A7 | 会话管理：登出、查看在线会话、管理员强制下线；空闲超时 8 小时、绝对超时 24 小时 | P0 | 登出后旧会话立即失效；被强制下线的会话下一次请求即 401 |
| A8 | 密码修改与管理员重置 | P0 | 修改需验证旧密码；管理员重置生成一次性密码，首次登录强制修改 |
| A9 | SCIM 2.0 入站同步：企业 IdP 推送用户/组的创建、变更、禁用 | P1 | 用户在 IdP 禁用后下一次同步自动停用本地账号 |

### 模块 B：组织管理

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B1 | 组织 CRUD：创建、改名、描述、启停、归档（归档不删除数据，数据只读） | P0 | 只有平台管理员可操作；全部变更审计 |
| B2 | 用户组管理：组内增删用户、组直接挂角色（组授权与用户授权取并集） | P0 | 组权限变化对组内用户即时生效 |
| B3 | 组织级设置：每组织可指定默认角色、默认数据保留参数覆盖 | P1 | — |

### 模块 C：用户管理

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| C1 | 用户 CRUD：创建（用户名/邮箱/显示名）、编辑、停用（不物理删除，保留审计关联） | P0 | 停用后所有会话与 token 立即失效 |
| C2 | 多组织成员关系：一个用户可属于多个组织，每个组织一个角色，其中一个为默认组织；用户可切换当前操作组织 | P0 | 切换组织后，所有后续请求的数据上下文随之切换；无成员关系的组织切换被拒绝 |
| C3 | 用户视图：管理员查看用户的组织、角色、会话、token、最近登录 | P0 | — |
| C4 | 平台管理员角色授予：全局角色，跨组织 | P0 | 平台管理员不属于任何组织也能管理组织 |

### 模块 D：授权（Authorization）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| D1 | 权限点体系：全平台权限点统一注册（`resource:action`），服务在启动时声明所需权限点，iam 校验注册清单 | P0 | 未注册的权限点在 API 上使用时启动失败（防拼写错误） |
| D2 | 预置角色：`platform_admin`（平台管理员）/ `org_admin` / `analyst` / `viewer`，各自绑定固定权限点集合 | P0 | 预置角色不可删除，可被平台管理员复制后定制 |
| D3 | 自定义角色：组织管理员在权限矩阵页勾选权限点创建自定义角色 | P2 | — |
| D4 | 菜单权限派生：每个前端菜单/页面声明所需权限点；`GET /me/permissions` 返回当前用户权限点集合，前端据此渲染菜单与按钮 | P0 | 修改角色权限后，用户刷新页面菜单即时变化；直接请求无权限的 API 返回 403 |
| D5 | API 级权限校验：每个端点声明权限点，中间件统一校验 | P0 | 声明式（装饰器/依赖），业务代码不出现手写权限判断 |
| D6 | 权限点清单 API：`GET /permissions` 返回全量权限点及说明（供管理界面与文档） | P0 | — |

### 模块 E：令牌与机器身份

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| E1 | 浏览器会话：httpOnly + Secure + SameSite cookie，服务端存储可吊销 | P0 | 见 OWASP 会话管理对照（技术设计 §5.3） |
| E2 | API Token：签发（名称+过期+权限范围）、展示一次、哈希存储、即时吊销、最后使用时间记录 | P0 | Token 泄漏后吊销立即生效；权限范围小于等于签发者权限 |
| E3 | 服务间 JWT：服务以平台身份签发短效 JWT 调用彼此（内部 RPC/队列消费） | P0 | 验签本地化（公钥缓存），iam 不可用不影响已登录用户（见 NFR3） |
| E4 | 刷新令牌轮换 + 重用检测：刷新令牌一次性，检测到已用令据重放即吊销整个令牌族 | P0 | 重放测试：旧刷新令牌第二次使用 → 全族吊销并审计告警 |

### 模块 F：数据隔离（策略声明；执行见技术设计 §8）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| F1 | 告警的 org 归属在采集落定时确定（连接器默认 org + 资产映射覆盖），落库后不变 | P0 | 归属规则在 collector 配置，归属字段不可由 API 修改 |
| F2 | 三层数据可见性：全局共享（威胁情报 IOC、规则库、ATT&CK 映射）/ 组织隔离（告警、案件、Ledger、事件视图）/ 组织隔离（**机构记忆、实体档案**） | P0 | §10 验收场景 1 全部通过 |
| F3 | 数据库层强制：组织隔离层的每张表启用行级安全（RLS），即使应用代码有漏洞也不跨组织泄漏 | P0 | 关闭应用层过滤、仅靠 RLS 的测试同样通过（双保险各自独立可测） |
| F4 | 全局共享层的管理权限：仅平台管理员可写全局层（如导入情报），所有组织可读 | P0 | — |

### 模块 G：管理界面（console 的 iam 域页面）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| G1 | 组织管理页：列表/新建/编辑/归档/成员概览 | P0 | 对应 B1 |
| G2 | 用户与角色管理页：用户列表（按组织过滤）、成员与角色分配、角色权限矩阵（权限点 × 角色勾选） | P0 | 对应 C1/C2/D2 |
| G3 | 会话与 Token 管理页：在线会话列表与下线、API Token 签发与吊销 | P0 | 对应 A7/E2 |
| G4 | 登录安全页：密码策略、锁定策略、OIDC 配置、MFA 强制开关 | P0 | 修改即生效并审计 |
| G5 | 组织切换器：多组织用户顶栏切换当前组织 | P0 | 对应 C2 |

### 模块 H：审计与自举

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| H1 | iam 全事件审计：登录成功/失败、锁定、MFA 绑定、组织/用户/角色/权限/token 的全部变更，append-only 哈希链 | P0 | 审计记录含操作者、对象、前后值摘要、来源 IP；不可篡改（复用全平台 audit 链） |
| H2 | Bootstrap 管理员：首次安装创建 `admin` 平台管理员，密码一次性打印，首登强制修改 | P0 | 与"安装即验收"衔接：安装脚本最后一步验证 admin 可登录 |
| H3 | 高危变更二次确认与通知（角色权限变更、平台管理员授予） | P2 | — |

## 6. 非功能需求

| 编号 | 类别 | 需求 | 量级依据（单部署几十–几百用户） |
|---|---|---|---|
| NFR1 | 安全 | 对齐 OWASP Authentication / Session Management Cheat Sheet；凭据与令牌的存储、传输、吊销全部有据可查 | — |
| NFR2 | 性能 | 登录 < 500ms；每请求验签+权限校验 < 5ms（本地缓存策略快照，不查库）；管理页操作 < 200ms | 用户量小，性能不是瓶颈；**校验不查库**是硬要求（见 NFR3） |
| NFR3 | 可用性 | iam 宕机 10 分钟：已登录用户工作完全不受影响（验签走本地缓存），仅新登录与用户管理不可用 | 验签不依赖 iam 进程存活是"权限单点收敛"的同时不引入"可用性单点"的关键 |
| NFR4 | 可维护性 | 新增权限点 ≤ 3 步、新增业务表获得自动隔离 ≤ 4 步，均有 SOP（技术设计 §14）；权限点拼写错误在 CI 拦截 | 用户核心诉求："不了解项目的人也不会改错" |
| NFR5 | 可扩展性 | ABAC（P2）、SCIM（P1）、SAML（P1）、Zitadel 整体外包认证，全部为"加法"演进而非重构 | 对应 §2.2 非目标 |
| NFR6 | 合规 | 审计日志满足等保"可追溯"要求；密码不落明文、不进日志；token 哈希存储 | — |
| NFR7 | 可移植性 | 全部组件运行于信创环境（arm64/amd64、麒麟/UOS/欧拉），无外部强依赖（内网无外联时 OIDC 功能优雅降级为本地账号） | 部署架构篇约束 |

## 7. 关键用户流程（业务视角）

```
① 登录：用户提交账号密码（+TOTP）→ iam 校验 → 签发会话 cookie（含当前组织）
② 日常请求：携带 cookie → 中间件验签 → 还原 {用户, 组织, 角色, 权限点} → API 校验权限点 → 数据层按组织隔离
③ 切换组织：用户在顶栏选择另一组织 → 校验成员关系 → 会话重签（当前组织切换）→ 后续数据上下文切换
④ 权限变更：管理员在权限矩阵勾选保存 → 审计记录 → 用户下一次请求权限快照刷新 → 菜单变化
⑤ Token 管理：管理员签发 API Token（选权限范围、有效期）→ 明文只显示一次 → 可随时吊销
⑥ 首次部署：安装脚本创建 bootstrap admin → 打印一次性密码 → 登录强制改密 → 创建组织 → 邀请用户 → 开始接入告警
```

## 8. 依赖与约束

- 上游依赖：无（iam 是最底层服务，其他所有服务依赖它）
- 下游被依赖：全部 9 个自研服务（验签与权限点校验）、web（/me/permissions 渲染）、collector（org 归属规则存储）
- 约束：Python 3.12（secplexus 单镜像的角色之一）/ PostgreSQL 16 / Redis 7（架构总纲已定）；部署形态受部署架构篇约束（standalone 单容器至 k8s 全形态可用）

## 10. 验收场景（端到端，全过才算达标）

| # | 场景 | 预期 |
|---|---|---|
| 1 | 组织 A 分析师尝试读取组织 B 的告警/案件/机构记忆/实体档案（走 API、走查询语言、构造带 org_id 参数的请求三种方式） | 三种方式全部拿不到；第三种被数据库层（RLS）兜底拒绝 |
| 2 | 移除 viewer 角色的 `soar:approve` 权限点 | 该角色用户刷新后看不到审批菜单；直接调审批 API 得 403 |
| 3 | 连续输错密码 5 次 | 第 6 次锁定，正确密码也拒绝，15 分钟后自动解锁，全程审计 |
| 4 | 签发只读 Token → 吊销 → 立即用该 Token 调 API | 吊销后 401 |
| 5 | 重启 iam 进程 10 分钟 | 已登录用户所有操作正常（验签本地缓存），仅新登录失败 |
| 6 | 开发者新增带 `org_id` 的表并注册实体，不写任何过滤代码 | 两个组织互不可见对方数据（自动隔离） |
| 7 | 对接 OIDC（任选 Keycloak 或飞书） | 配置页填入端点/ID/密钥后，跳转登录成功，自动建号进入默认组织 |
| 8 | 用已用过的刷新令牌再次刷新 | 整个令牌族被吊销，产生审计告警（重用检测） |
