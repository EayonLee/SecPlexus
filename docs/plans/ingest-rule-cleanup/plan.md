# 清理旧版解析规则与多行合并实施计划

1. 用边界测试覆盖旧格式、多行配置及旧事件契约的拒绝。移除双路径编译、试算、运行和归档逻辑。
2. 新增 PostgreSQL 前向迁移，在事务内处理接入点引用、规则、修订和约束。迁移只扫描有限的管理配置及修订表，不锁定事件归档，也不在接收热路径查询 PostgreSQL。停写后上线，迁移失败由事务回滚，成功后清理的数据只能从已保存的备份恢复。
3. 删除旧编辑器、相关文案和规则分帧控件。沿用当前规则工作区及共享表单布局。本次保留现行字段映射交互。
4. 用隔离 PostgreSQL 验证迁移前后状态，验证现行模板、消息边界、现行事件发布归档以及 Web 主流程。发布前排空旧写入产生的 Kafka 积压，并确认受影响接入点的重新配置。

## 验收

- 真实 PostgreSQL 验证了清理、接入点解绑与停用、当前规则引用和修订保留，以及不可逆迁移回退时的状态保护。
- Go 测试覆盖拒绝旧规则与多行配置、HTTP 批量与 TCP Syslog 消息边界、当前 Event 投影和旧契约拒绝。SQL 生成和迁移边界检查通过。
- Web 类型检查与 76 个单测通过。Chromium 验证两个删除项、新建与编辑自定义规则、HTTP 推送与 Kafka 发布，并验证 FortiGate 混合样本可从 ClickHouse 回查。
