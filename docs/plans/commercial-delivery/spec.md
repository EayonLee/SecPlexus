## 共享事实与术语

| 含义 | 唯一权威来源 | 使用方式 |
| --- | --- | --- |
| 事件类别、事件类型、字段、枚举、必填约束 | Ingest 的 `event-contract.json` 和锁定的 OCSF 1.10.0，生成 `catalog.json` | 平台契约保持 `v1`。类别由 `category_uid` 标识，事件类型由 `class_uid` 标识。规范路径、编码、类型从上游生成，中文名称和平台补充约束在契约源维护。Web 通过授权 API 发现运行目录，发行包随附锁定目录及摘要，后台消费者按公开契约读取。 |
| 数据接入、解析规则、规则修订和生效边界 | Ingest PostgreSQL | `mapping_id` 指向解析规则。修订内容不可变。定义、修订和运行时快照按所有者派生，其他模块经 API 或公开消息消费。 |
| 用户、权限及审计 | IAM 权限目录、IAM PostgreSQL 及 Ingest 管理审计出箱 | 迁移任务应用权限目录，常驻 IAM 读取并核对。Ingest 写入和待投递审计同事务，IAM 保存原始发生时间并按事件 ID 去重。 |
| 接入观测 | Ingest 对各接收实例的观测投影 | API 告知观察范围、时间和汇总完整性。Web 显示服务端状态。Prometheus 用于运维告警。 |
| 可安装制品和支持环境 | 一份版本化发行清单 | 安装、预检、CI 和运维手册引用同一份清单。应用配置仍由模块 YAML 和公共环境模板声明。 |

术语表区分「接入协议」「解析类型」「事件类型」。HTTP、Syslog、Kafka 是接入协议。JSON、CEF、键值对、正则表达式、分隔符属于解析类型。认证活动、网络活动等是事件类型。将规则摘要及筛选对外的 `format` 收敛为 `parse_type`，与规则定义里的解析器设置一一对应。落实时同步 DTO、查询、Web 类型和测试，数据库继续从定义派生筛选值。列表「数据接入」列表示**引用该规则的数据接入数量**。保留同一规则外键和统计来源。

## 发行和部署（#2、#10、#16）

交付一份可验证的 Compose 安装包。以 Linux amd64 为验收平台。发行包包含 HTTPS 入口、Web、IAM、Console、Ingest、一次性迁移任务和基础依赖。具备归档的安装启用 ClickHouse 和同一 Ingest 镜像的 `store-events` 进程。部署支持随包运行的基础组件和按支持矩阵配置的外部依赖。每套部署服务一个运营团队。

- CI 按 Git tag 构建一次。发行清单记录 Git 提交、服务和依赖镜像摘要、配置及迁移摘要、支持的操作系统和架构、数据库和 broker 版本、归档组合。制品随附校验文件、SBOM 和签名验证材料。装包和升级均按摘要拉取，经内网镜像或离线导入仍校验同一份清单。证书材料和用户密钥由部署方提供。版本号、标签和摘要不能由运行节点分别推断。[AiSOC 制品验证](references.md#发行安装与恢复)
- 预检依次核对运行环境、磁盘和端口、必填配置、TLS、依赖权限、持久卷、版本及数据边界。Kafka 要实际读主题元数据并核对 ACL、分区和保留策略。ClickHouse 要校验库、写入与读回所需权限。由部署任务检查管理权限，常驻服务只获得各自运行所需的访问权。检查输出只给出资源名、失败阶段及处理入口。安装、迁移和重试均复用已有卷与业务标识。对已存在数据的卸载或重建保留独立的显式操作。
- PostgreSQL 和 Redis 复用现有实例边界。部署名称用于生成或校验 Kafka 主题、归档消费组及 ClickHouse 库名，权限按这些资源分配。安装的管理元数据保存部署名称与资源标识，预检发现已有数据与本次部署不匹配时停止。接管已有客户环境须验证原安装记录和资源权限。支持矩阵中的正式 Kafka 基线与集成夹具对齐，评审基线采用当前架构文档的 4.2.2，版本变更通过清单和依赖验收统一办理。
- 同份发行包在干净机器走通管理员初始化、三种协议接入、Kafka 确认、预期解析失败的诊断和归档回查。TLS、Cookie、SSE 和独立协议端口均从实际发行入口测试。[Wazuh 和 Malcolm](references.md#发行安装与恢复)

## HTTPS 入口、身份和审计（#3、#11、#12）

交付入口使用 NGINX。公网仅暴露 Web HTTPS 和明确发布的设备端口。内网调用服务直接使用服务地址与各自的服务凭证。Web 仍负责现有同源用户 API 及设备 HTTP 转发。

1. 入口依据连接对端确定客户端地址。上游有负载均衡时，只有配置在可信网段的代理节点可以提供来源地址。入口重建转发头，Web 只接收入口网络的流量并向 IAM 转发该受控地址。IAM 只信任此转发链，并继续校验公开 `Origin`、会话与 CSRF。Keep-Alive、SSE、多 `Set-Cookie`、`Retry-After`、请求 ID 和设备 Bearer 的既有语义纳入交付测试。双客户端登录限流、来源变化和直连隔离必须穿过实际入口验证。[入口实践](references.md#入口信任与数据最小化)
2. 一次性迁移任务持锁应用 schema、权限目录和首次管理员初始化。常驻服务启动只核对目标迁移和目录摘要，运行角色对权限目录只有读取权限。升级时顺序排空并替换同套实例。升级前后均核对正常授权、退役键和审计行为。数据库实例共用，迁移任务与运行时权限在部署侧授予。运行应用使用原有连接配置模型。
3. 配置启停、轮换、规则恢复及位移变更均沿用管理鉴权和持久审计。业务事务保存目标及修订，投递侧保留发生时间。告警覆盖出箱深度和最老等待时间。错误跨边界通过请求 ID 和受控原因关联。试算样本、会话及设备凭据不会进入出箱、运行日志和支持包。

## 规则试算、发布与追溯（#4、#7、#14）

保留「基础配置 → 提取字段 → 字段映射 → 预览保存」的一套页面骨架，用于新建、编辑和查看详情。采样交互遵循阿里云与 Elastic 的区分：操作员可看源字段、标准字段、缺失值和解析结果，选择标准字段的必填义务由事件类定义。试算在当前规则上下文运行。[样本与修订实践](references.md#规则试算字段映射与修订)

### 请求和样本生命周期

- 一套 Ingest 样本验证负责数量、空值、UTF-8 解码后字节、类型对应的解析结果、错误位置。规则向导及其提取、验证和规则写入使用 20 条、单条 64 KiB 的同一上限。原始请求还需满足包体预算，考虑 JSON 转义放大和规则定义大小。发布时在同一请求中用最终定义重新验证本次样本，避免保存上次预览的结果。
- 新建或修改实际解析行为需要至少一条能产生所选事件类的样本。新建规则仍先选一个事件类型。保留适用输入下已有的按内容分流能力时，变更的可达分支分别需要有效样本。全部失败阻止应用，少量运行期缺字段可作为带问题的结果由操作者确认。只改名称和描述、恢复已经验证过的同一有效定义，服务按定义摘要验证来源与适用上下文，可复用验证记录。
- 原文仅在当前编辑会话和有界试算请求中存在。日志样本只作为请求级输入。拒绝 `definition.samples`，数据库规则 JSON 和修订 JSON 只保存规则。旧开发数据里的样本键在正式基线前清理，当前旧制品已写入的样本不随支持包或迁移日志导出。需要日后复测时，支持公开或合成的脱敏测试夹具，和运行规则分开提交。API `GET` 详情只返回定义、上次验证的摘要结果和生效信息。
- 复用现有安全字段投影，补充嵌套对象、数组、正文及错误反馈的输出测试。逐条错误返回样本序号、字段路径或可控原因。试算界面能就地修正，越界只显示截断状态和人工可读原因。异常响应与追踪记录不回传原始内容。

## 接入状态、凭据生效和监控（#5、#6）

| 状态维度 | 判定和展示 |
| --- | --- |
| 管理状态 | 数据接入的启用或停用，由持久配置决定。 |
| 配置生效 | 当前期望修订为 `r`，相关运行入口已确认 `r`，且未确认的旧实例已失去受理资格，显示「已生效」。启用与轮换要求至少一个预期接收入口可用。停用可在所有旧入口失效后确认。仍在切换时显示「正在应用」。编译或连接失败显示阶段和重试入口。 |
| 接收与发布 | 接收指服务受理一条逻辑日志，发布指 Kafka 已确认，两个时点各自记录。首条确认、最近确认时间、统计窗口和是否完整由服务返回。无历史确认且观测链健康时显示「等待首条日志」，已有历史、超过配置的活跃窗口时显示「最近无数据」，观测过期或缺失时显示「暂不可确认」。 |
| 归档 | 未启用、运行、积压、故障各有状态。Kafka 已确认和 ClickHouse 已归档分开计量。告警包含消费组和影响分区。 |

Ingest 从 PostgreSQL 批量刷新配置。以每来源独立的编译结果替代全量加载失败时保留全部旧条目的模式。解析规则编译失效只影响该来源。暂停和轮换读取同一来源的凭据代次，即使新规则编译失败仍能回收旧权限。运行快照须持有有界有效期，避免断连实例继续无限使用旧配置。计划值为 5 秒刷新、15 秒最大有效期，按本地单调时钟验证。确认收到旧凭据撤销后终止该代次的新接收，已有受理按协议执行排空。失去配置权威超过有效期的实例停止受理相关来源并说明原因。Kafka 规则切换另按分区连续位移执行。

产品统计由 Ingest 通过已有 Redis 汇总时间桶和最后确认时间。节点内先计数，带实例纪元和批次序号合并，重试一次效果相同。时间桶有 TTL，已删除来源停止新增统计。记录观测新鲜度后再决定能否展示计数。指标侧允许有界采样，产品状态覆盖所有登记来源。每条事件不写 PostgreSQL。对账时以真实 broker 和归档数据为准，页面中的收包、已发布、待归档各自保留明确口径。复用健康探针及指标，增加位移缺口、最老未归档消息、配置快照龄、投递积压与受控错误阶段。运维告警应带任务入口和排障路径。[同类产品状态](references.md#接入诊断与运行观测)

## OCSF、事件身份和回放（#8、#9、#15）

1. 生成链固定上游 OCSF 1.10.0 与编译器输入摘要。当前目录逐类对照上游，包括可写核心字段、平台生成字段、类适用字段、枚举和条件组。`metadata.product` 等嵌套必填项纳入验证。对 OCSF 的基础事件保留运行期未分类用途。CI 将平台扩展生成独立的验证描述，使用锁定的上游编译 schema 及独立校验工具检查实际发布 JSON。物理层核对写入列、类型、UTC 毫秒、保留策略和排序键。类样本要包含缺失、空值、零、条件触发和不匹配编码。[OCSF 规范与验证](references.md#标准事件与重放)
2. `category_uid` 和 `class_uid` 维持 OCSF 的原始编码与含义。类别的分组标签与具体事件名称分层显示，例如「网络类 → 网络活动 / HTTP 活动 / DNS 活动」。兼容搜索可包含英文名和常用别称。中文枚举建议保留用户认识的动作词，协议关键字原样展示。HTTP 状态码按 RFC 范围和 IANA 注册值提供快捷建议，保持与 OCSF 活动枚举分开。所有术语由契约源生成，页面不做本地分类翻译。[术语与映射对照](references.md#规则试算字段映射与修订)
3. Kafka 来源记录标识和标准 Event ID 分开。前者标识原始来源位置，由接入标识、来源代次、broker 的主题身份、分区和位移限定。标准 Event ID 标识该来源记录的一次规范化产物，由来源记录标识与已固定的执行版本生成，记录规则、契约和来源配置版本。自动重投同一逻辑产物时，ID、事件时间、类别、输出内容和归档键一致。手工按另一套规则重新处理时，产生可追溯的新产物，各版保有同一来源关联。UI、查询和后续应用区分「同一来源」与「同一 Event」。[Kafka 与 ClickHouse 语义](references.md#标准事件与重放)

### Kafka 切换边界

首次启动显式选择起始位置。正常重启使用已提交位移。已有位移超出保留期时停止该分区，报告期望范围和实际可用范围，后续重置由有权限的操作者确认并审计。

应用新执行版本前，该接入的消费组暂停拉取并排空旧批次。发布确认且旧连续前缀的下一条位移已确认后，Ingest 用每分区边界写入新修订生效记录。生效记录按来源、分区、起始位移排序，进入消费循环前加载，不在逐条处理时查库。重平衡和崩溃后按同一边界选择规则。旧批次确认不明时继续按旧版本重试，切换记录保持待完成。边界更新由来源记录的条件写和 Kafka 分区所有权约束，旧实例不能覆盖新边界。新增分区建立独立的初始边界。保留至少覆盖来源主题的可重放窗口与归档证据追溯期限。

外部 Kafka 与平台 Kafka 视为独立确认域。设计以分区连续提交和下游逻辑幂等承担重试。HTTP 只确认已发布前缀，确认未知时设备可能重发，协议文档明确重发口径。Syslog UDP 无送达确认，监控区分内核丢包与解析失败。恢复归档时重读已经发布的标准事件字节。按新规则重新解析由 Ingest 的维护任务执行，带显式范围和修订记录。需要正式统计时采用确定的产品查询口径，ClickHouse 保留有时间范围的 `FINAL` 或等价去重。[投递边界对照](references.md#标准事件与重放)

## 升级、恢复与容量（#11、#12、#13）

- 迁移制品可追溯。每个 ClickHouse 修订冻结当时的列、默认值、约束和注释。实际保留策略按部署配置单独核对。历史校验与最新字段目录脱钩，最后再核对实际 DDL 与本次目标投影。IAM、Ingest 和归档有各自账本。运行只接受发行清单中兼容的迁移组合。错误显示阶段、版本和受控原因。ClickHouse 重试前核对 DDL 的真实状态，再登记账本。
- 首个已发布制品成为升级基准。发布后已应用历史迁移保持不可变，前向升级作业带迁移预检、受影响范围、保留期和失败恢复分支。首版验证明确维护窗口。升级前先确认发布及归档位移并建立恢复点。应用新版本后按权限、已接入来源、标准流、归档与审计逐项放量。现有开发期删数据迁移和旧校验和处理在正式交付说明中明确标识。仓库持续保持一个 `v1` 事件契约。
- 恢复点记录制品摘要、PG/ClickHouse 备份标识、Kafka topic 与分区坐标、源代次、规则修订和密钥引用。用受控暂停和排空建立可核对的一致边界。备份及恢复材料按访问角色保护。恢复到隔离环境，确认旧 IAM Session 撤销、接入/规则历史完整、主题位移仍可达、事件回查和审计连续后再接收客户流量。Redis 运行状态恢复后在新观测窗口重新计算。位移超出保留期时输出明确缺失区间。交付手册提供可复跑恢复操作和实际测得的恢复点目标、恢复时间目标。[组件备份和恢复](references.md#发行安装与恢复)
- 持续 50,000 EPS 是当前待验目标。交付前在明确 CPU、内存、磁盘、分区与副本配置上，覆盖短 JSON、CEF、长日志、解析失败、HTTP/Syslog/Kafka 混合流量、归档检索、升级排空和依赖中断恢复。记实际拒收、丢弃、重复、接收至发布与接收至可查的 P95/P99、GC/RSS、Kafka 积压、ClickHouse 合并和磁盘使用。50,000 EPS 对应的规格须用混合长稳、对账和恢复结果证明。达不到当前目标时，保留失败结果并评审资源配置或正式调整产品承诺。[已有性能基线](../event-contract/performance.md)
