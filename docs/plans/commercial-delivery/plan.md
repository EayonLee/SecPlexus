## 实施批次

### A. 发行清单、安装和隔离

- 构建与发布维护者负责 `deploy/`、根配置入口和 GitHub Actions。定义发行清单的一次生成路径及依赖镜像摘要。把 Ingest、Kafka、HTTPS 入口、一次性迁移和可选归档补到实际可运行的 Compose。应用依赖只在其拥有的配置中声明。部署输入覆盖官方内置依赖和受支持外部依赖。
- 在真实连接前校验配置结构与必填项。连接后确认 Kafka topic 身份、保留期、ACL、消费组、归档数据库和迁移目录。资源名只从已校验的部署配置渲染，日志、报告和打包脚本排除私有配置。用支持矩阵生成集成依赖选型，确认项目依赖版本实际可拉取和运行。验证第三方许可证声明、SBOM、构建溯源和摘要。
- 测试空卷、已有卷、依赖尚未就绪、端口占用、目标磁盘不足、主题冲突和缺失部署权限。作用范围由当前 compose 项目和本次创建的资源决定。安装重跑不得重建客户表、重置消费位移或更换已初始化凭据。

### B. 可信入口和 IAM 迁移

- IAM 和部署维护者共同落实 NGINX → Web → IAM 的可信链。分开鉴权公共会话、内部服务和设备推送。限流和审计使用同一服务端计算的来源。安装文档给出直连入口及前置负载均衡两种受支持的信任拓扑。保留 Web 直接运行的本地开发配置。
- 将 IAM 目录和初始化写入移入一次性任务。已初始化环境按同一目录摘要幂等核对。进程启动验证，失败提示匹配的发行制品和迁移版本。运行数据库权限和任务执行权限在生产安装测试中实际断言。管理员账号、既有角色和审计对象由原模块维护。
- 端到端验证两名来源、权限收回、退出和 SSE 的授权续检。故障注入验证代理缺失可信信息、升级前后重复执行初始化、旧实例重启和记录审计时间的语义。与 A 一并形成真实入口验收。

### C. 字段目录、规则与样本

- Ingest 拥有上游锁定、目录生成、定义编译及试算验证。先把每类的独立契约夹具和现有规则用例归档为对照。对照 OCSF 属性、必需字段和类型，明确哪些由平台生成。更新规则 DTO、命名、`sqlc` 查询、Zod 和双语资源，测试对外键名、枚举和读写端一致性。由规则版本检查保护并发更新。
- 落实统一的试算输入、样本错误和单次提交验证。检查原文在请求、响应、浏览器缓存、日志、规则定义、版本表和备份边界的生命周期。保存摘要和修订。历史查询通过 `mapping_id` 与 `revision` 做有界分页，使用现有组合主键。恢复创建新修订，审计记录目标规则、旧修订和新修订。
- Web 沿用规则向导和现有表单组件。四步布局、样本高度、行内错误、焦点、标准字段排序和类型标签保持一致。增加历史与差异入口。使用相同的标准字段分组和枚举进行创建、编辑、只读及列表筛选。用真实保存、冲突与恢复核验。标注本地模板块和业务差异。[Web 设计依据](../../../src/apps/web/README.md#selective-template-adoption)

### D. 事件身份、Kafka 分区边界和归档

- 确定外部 Kafka 来源标识的组成与生命周期。为接入的来源代次和分区生效边界添加有约束的 SQL。控制面以接入标识条件写入，单次提交仅影响当前接入和相关分区。账本增长由规则生效次数乘分区数决定，按可重放窗口和证据留存清理。运行期在分区所有权变化时加载必要边界，缓存有上限。消息级路径只查只读快照并按原流程发布。
- 对活跃规则应用实现局部暂停、排空、确认连续位移和切换。先模拟多个消费者与中断。持久化的边界和来源代次负责恢复。发生未知确认时重新执行同一边界的旧批。归档读取标准流，验证不支持版本的隔离可诊断，位移缺口需要人工确认。SQL 迁移和重放验收同步检查规则修订引用。
- 验证 ClickHouse 在后台合并前也能按确定口径查回。验证 HTTP 确认前缀、Kafka 重试、Syslog TCP 停用与 UDP 丢包口径。核对 archive 连接和事件表归属。受控主动重算与日常重放分别测试并留审计证据。

### E. 生效反馈、接入诊断与运维观测

- Ingest 分离凭据有效期、期望配置、运行配置和接收观测。刷新使用批量查询和来源独立编译。旧实例故障时以缓存租期和副本心跳共同作出生效结论。校验来源删除、暂停、令牌轮换、规则编译失败和空来源启动。Redis 时间桶按部署、来源、时间、实例状态定界，定期刷新，不给 Kafka 热路径增加同步远程调用。
- 归档和审计出箱指标补最老等待时间及阶段原因。生产告警按队列、分区、丢弃、保留空间和确认延迟组织。每类告警有诊断入口和负责人。Web 展示最后接收、最后发布、应用状态、观测是否可用。使用现有列表、详情和抽屉。只在失败时出现原因和重试动作。
- 使用两实例、多于旧统计额度的来源和新实例重启验证不误报。人为降低 broker 或归档可用性，在页面、指标和日志中核对同一事实。明确「配置已保存」到「全部入口已生效」的时限与失败原因。

### F. 升级和恢复演练

- 数据库维护者冻结 ClickHouse 各历史迁移及结构预期。启动结构检查使用目标发行投影与部署的 TTL。准备空库、旧修订、DDL 已执行账本未登记、账本存在但结构偏移四类测试环境。确认每种失败都能定位并幂等重试。
- 编排停止接收、排空、备份验证、记录位移、迁移、启动、业务检查与失败恢复。发行制品、配置摘要、备份和恢复点对应。跨版本无已验证运行窗口时使用明确维护窗口。升级回退提取数据兼容条件，破坏性变更依赖备份恢复。受支持路径以第一个已发制品为起点，试制旧数据作为有明确处置范围的开发资料。
- 在新环境恢复 PG 和 ClickHouse。撤销旧会话，核对权限、接入及规则历史。核对 Kafka 位移仍处在有效窗口，恢复消费后抽查标准 Event 与审计。备份检查要实际读回。支持包仅包含受控的版本、结构、位移与诊断数据。

### G. 真实发行包验收和文档收口

- 在发行清单硬件与受支持依赖上完成联网和离线安装，保留冷启动、命令输出和安装时间。完成两个隔离部署、上一个可升级版本和恢复点验证。第一个发行制品无前驱时，保留它的镜像和数据测试夹具，内部迁移通过冻结修订样本验证。
- 容量覆盖至少 60 分钟混合稳态、8 小时长稳、约定的突发与恢复窗口。记录客户端发出、受理前拒绝、已确认、明确丢弃、隔离、可回查、重复和期末在途，说明口径及各协议限制。并发查询和归档积压恢复纳入实测。样本、制品摘要、主机规格、负载混合分布和测量命令可复跑。高成本长稳在发行验收环境执行。
- 更新部署架构、架构能力表、配置指南和模块 README，让客户从一个入口找到支持矩阵、安装、诊断、升级、恢复和现状。Web 与 Ingest 文档核对规则预览、修订、应用状态和语义。重大命名和版本变更附契约对照表。可用于其他模块的长期规范进现有开发指南，计划文档保留本次决策依据及验收结果。

## 交付验收记录要求

每个批次记录**触发条件、受影响的边界、证据和结果**。缺陷先用有确定结果的失败用例重现，再核对修改后的正常与异常操作。代码评审检查所有权、写入幂等、保留窗口、资源上限及可维护性。应用层错误由共享组件就地显示。商业交付测试使用与客户一致的制品，浏览器使用实际后端，测试环境的数据库、Kafka 主题及实例均独立。

最终评审查五份证据：

1. 同一发行摘要的安装和升级记录。
2. OCSF 1.10.0 各类实际发布样本及规则试算验证结果。
3. 可信入口、权限、样本生命周期、接入生效和规则恢复测试。
4. Kafka 追赶、位移缺口和整套恢复记录。
5. 持续和突发容量、端到端延迟、留存和资源规格。

## 实施记录

- 发行清单、HTTPS 入口、IAM 迁移、Ingest、Kafka 与可选归档已接入独立发行 Compose。发版工作流包含 Linux amd64 构建、签名、验签和隔离安装。隔离试验验证 PostgreSQL 和 Redis 的部署归属冲突拒绝、HTTPS 入口来源覆盖与响应透传，以及 ClickHouse 运行账号可以读写事件并被拒绝修改表结构。
- IAM 已测试常驻启动只核对权限目录。真实 Chromium 已覆盖规则创建、规则修订查看与恢复、只读访问、Kafka 向导和 HTTP 设备推送。用上游 OCSF 编译结果独立验证了 12 类实际管道产物。
