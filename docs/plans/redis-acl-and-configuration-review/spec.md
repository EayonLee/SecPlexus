# Redis 用户配置与配置链路审查

依据本次明确要求实施，不扩展尚不存在的业务功能。

- IAM 的 cache 增加 user 字段，通过 SPX_REDIS_USER 注入，默认 default。与 host、port、password、db 一起构造连接，完整 URL 仍优先；URL 编码保留用户名、密码中的特殊字符。
- 自有 Compose 的 Redis 按同一用户名与密码设置 ACL，健康检查使用对应用户；自定义用户时禁用默认用户，不向容器进程参数放明文密码。空密码仍支持明确配置的无密码连接。外部 Redis 只连接，不擅自创建或修改用户。
- 初始化管理员默认密码统一为 secplexus；删除只为旧短密码默认值存在的特殊哈希入口。所有新设密码统一遵守 8–128 字符，已有账号与密码不因启动配置变化覆盖。
- 审查既有计划及当前配置、启动、认证授权、Result、日志、迁移边界；修复能复现的当前问题，记录覆盖与剩余事项。不接管正在独立实施的 Web 工作台变更，不把历史被替代任务算作新需求。
- 本地单元、真实 PG/Redis 集成及必要的 Playwright 核心流程验证。开发容器、数据卷保留；不提交、推送、执行远程 CI 或生产部署。
