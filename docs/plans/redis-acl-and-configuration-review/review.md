# 本轮审查记录

范围：已有计划索引及未勾项，IAM/Console 配置与启动、路由注册、请求绑定和 Result、认证及授权、密码管理、迁移、ORM 日志、共享配置/缓存 key/HTTP 能力，以及对应稳定测试。仅记录有依据的问题，不以本次抽查宣称全仓无缺陷。

## 已确认并修复

1. Redis 结构化字段缺少用户名：只能在完整 URL 中指定，不符合数据库/缓存字段配置习惯。新增 cache.user / SPX_REDIS_USER，保留 URL 优先和安全编码；Compose 同步建立用户与 ACL，并使用该用户做健康检查。外部服务只连接。
2. 默认密码修改后仍有专用短密码哈希入口：删除旧初始化例外，初始化、创建、重置及主动改密共用正常 Hasher。默认管理员密码、PG 和 Redis 均为 secplexus，更新本机连接与基础服务；不通过初始化覆盖现有账号。
3. Redis URL 的格式错误推迟到依赖创建阶段：改为配置加载时验证；不建立网络连接，不在错误中回显 URL/凭据。
4. 正常请求取消被 handler 映射为内部错误、ORM 记录 Error，导航产生错误告警。增加取消错误映射；父请求确实取消时记录 Debug。通过低层稳定测试确认行为，不增加工单式 E2E。
5. 维护入口复制了改密 SQL：复用已有身份版本递增和密码写入仓储方法，仍使用原事务，保留锁、撤销和审计。
6. Cache 注释仍提到已移除的可配置前缀、测试名仍含 Prefix：同步注释命名；spx 前缀保持固定的类型化模板。

7. 工作台模板清理后，E2E 仍在多处查找已删除的“进入管理中心”首页按钮，完整运行出现 4 条流程失败。按现有外壳的管理中心下拉入口更新断言与点击路径，保留权限分层、角色编辑和多标签场景；不为旧断言恢复重复产品入口。

8. Redis 的 shell 启动方式绕开官方入口的进程降权；已核对镜像内入口脚本及实际 PID 1 的 UID。ACL 组装完成后交回官方 docker-entrypoint.sh 启动 Redis，复用其目录权限处理和降权逻辑，不自行实现用户切换。
