# spx-code-standard 技能设计

状态：用户已确认；技能已创建，验证与完成情况见 Plan。本技能用于项目开发和用户手动发起的代码质量审查。

## 目标与边界

帮助开发者定位项目已有的规范、选择直接且清晰的实现，并报告有证据的质量问题。遵守 [AGENTS.md](../../../AGENTS.md)；接口以 contracts 为准，已实现业务以模块 README/代码为准，正在评审的目标以对应 Spec/Plan 为准。发现它们不一致时报告差距，不把候选设计当成现状。

不复制另一份 AGENTS、错误码注册表或架构手册；不引入新框架、万能检查器、尚不存在的语言服务或跨层规则。保留必要授权、业务状态、事务和资源释放；对推测性边界先说明实际触发条件和成本，不自行扩大代码或测试。

## 两种使用方式

| 模式 | 行为 | 交付 |
|---|---|---|
| 开发 | 读取当前需求、相关实现与契约；按任务选择规则，在请求/配置边界完成一次结构校验，直接传递类型化值；只为真实复用或独立职责抽取 helper/interface | 清晰实现、匹配验证及剩余差距；不因为启用技能自动重构全仓 |
| 审查 | 用户指定 diff 或范围；追踪必要调用方、权限/事务路径和对应测试，区分确定问题与待验证风险 | 按严重性给位置、触发条件、影响和可执行建议；无问题也说明覆盖范围和未验证项 |

审查默认只报告，修复需用户授权；技能不授权 Git 写入、部署或多 Agent 委派。开发中的 UI 操作遵循 AGENTS 的 Computer Use 规则，不在本技能另写一套委派流程。

## 项目专项规则

- **职责**：路由集中注册，按业务分组；handler 不直接查库，共享包不依赖应用私有实现，服务不读其他模块私表。简单流程不机械加层，接口不以方便 Mock 为唯一理由。
- **契约**：检查 Result、HTTP 状态和错误码一致，生成物不手改；流式/204 保留协议例外，Session 提交失败及已开始响应的行为明确。具体字段直接引用 contracts。
- **业务**：对本次变更涉及的授权、组织范围、管理员保护、版本检查、事务与审计追踪实际执行路径；不把本次未涉及的所有边界变成必修项目。
- **缓存与配置**：模板集中管理，默认显式包含 `spx:<模块>:<业务>:`，按模块文件划分。当前模板在 `src/packages/go/cache/key/iam.go`。环境变量在配置边界读取，不预建驱动框架。
- **可读性**：按 AGENTS 与[排版示例](../platform-service-architecture/code-style.md)检查中文注释、名称、方法间空行和逻辑分段；不以更短、固定行数或 helper 数量判断质量。
- **验证**：采用最低必要层次，优先已有稳定用例；真实集成验证组件契约，E2E 验证少量核心流程。临时复现不自动进入长期套件，格式通过不等于业务正确。

`spx-code-standard` 统一工程规范、保持行为的代码简化及质量审查；旧简化技能已按用户要求合并并删除。组件用法由根目录的官方 `shadcn` Skill 负责，不重复维护组件手册。

## 结构与验收

`SKILL.md` 保留触发场景、权威来源、最短开发/审查流程；仅在正文确实放不下稳定专项规则时增加 `references/`，不预建目录或脚本。制作时按 `skill-creator` 校验。

用真实代码和少量成对的临时样例验收：正常实现不被误报；明确违规能定位原因和位置；未实施目标不被当作当前强制规范；审查模式不擅自修复或扩大范围。不要求穷举所有规则、生成全套样例库或新增永久 E2E。若误报来自规则过度绝对化，先修正规则，而不是要求业务为技能改造。
