# 平台架构与已交付模块审查

目标是让维护者在新增应用或演进字段时，能够定位业务所有者、权威定义、实际读写入口和应执行的验证。本计划贯穿现有四个可运行应用以及规划中的归档与关联能力。已有功能按正常入口和已发布契约审查。下列标准在相应模块实施时验收。

## 业务、数据及权限边界

| 对象或行为 | 所有者及事实来源 | 协作边界 |
|---|---|---|
| 用户、会话、权限、管理审计 | IAM；PG 保存业务记录，Redis 承担已声明的缓存/限流职责 | 模块在其业务路由校验当前用户和对应权限；敏感操作可追踪到用户与请求。 |
| 接入点、厂商、产品、解析规则与版本 | Ingest；PG 中的模块表 | 接入身份、厂商提供的值、规则配置、平台生成值分开。Web 通过 Ingest API 操作。审计与写事务保持已有的可靠性。 |
| 标准 Event | Ingest；版本化 JSON 定义语义，Kafka 发布，独立归档消费组写 CK | 单条记录通过同一套类别、类型、枚举及必填校验。标准消息、解析失败、归档失败可区分，保留重放依据。 |
| Alert 与证据 | 规划中的 correlator；PG 保存告警状态及证据引用 | 规则版本、命中时间、证据三元组标明发现依据。一个 Event 可关联多个 Alert。案件长期保留所需证据有独立快照。 |
| 运营工作台、案件与调查 | Console 负责自身业务及必要的只读汇总；Web 提供交互 | 域间查询通过拥有者的契约或已声明的数据投影；区分未归档、已过期与权限不足。当前 Console 的 SSE 返回授权会话上下文，并非标准事件的数据源。 |
| 模型调用 | 规划中的 llm-gateway 管理供应商凭据与调用 | 分析工具从已发布契约取得字段意义、单位和枚举；提供给模型的事件需经过字段筛选和脱敏。 |

对每个已交付用例，从前端或协议入口依次追踪鉴权、业务规则、持久化、审计、响应或消息；有异步消费时再追踪提交位移和重试。记录每段所有者、失败结果、恢复方式及现有测试。审查覆盖 IAM 登录和授权变更、Console 上下文/SSE、Ingest 三协议和规则编辑、Web 跨模块操作。本期规划涵盖 Event 归档。correlator 与 Alert 仅作未来消费者示例，具体实现另行立项。

## 各应用的共同开发方式

| 约定 | 已落地基线与目标 |
|---|---|
| 查找与运行 | 每个可运行应用在 `src/apps/<module>/README.md` 说明职责、输入输出、依赖、启动/配置检查、必要迁移、测试、排障和部署覆盖情况。根入口支持按模块选择启动；构建与停止按照各自已公布的参数使用。独立运行与根编排使用相同的模块配置语义。 |
| Go HTTP 应用 | 统一 `cmd/`、`config.yaml`、`internal/{config,bootstrap,router,handler}/`，注册路由、装配依赖、响应和优雅退出职责一致。独立 HTTP 模型放 `internal/model/`；业务逻辑按领域放置，真正有事务或存储的模块才引入 repository、migrations 和 sqlc。IAM 的维护子命令保留在 IAM。 |
| Web | 保留 Next.js 的 `src/app/`、模块 API、共享组件、语言资源和本地测试目录。以路由、权限、目录版本、错误语义与后端对接。菜单、筛选、编辑、空态、加载与可恢复失败复用现有组件。 |
| 数据与异步消费 | PG 模型、goose 迁移和 sqlc 归模块，CK 投影与迁移归 Ingest。后台消费可按负载与故障独立运行，明确队列、取消、背压、重放及数据库不可用时的行为。 |
| 依赖和新增应用 | 跨应用使用 HTTP、显式版本的消息或已发布的共享消费契约。列出模块需获得的环境变量、端口、命令、健康语义，以及支持的源码、镜像和 Compose 方式。共享代码具备实际调用方。新模块按能力接入同一套检查，规划中的模块在有实现时接入。 |

Go 与 Web 共享职责边界、命令语义和验收方式，各自保留框架约定。以当前无表的 Console 为例，目录检查应接受它没有 migrations 和 sqlc；增加自有持久化资源时再启用相应规则。统一要求落入现有开发指南、模块 README 与必要的自动检查，项目总规则只保留长期原则与入口。

本轮对齐以 [Go 后端目录和 Gin 边界](../../development/backend-structure.md#gin-路由与-http-边界) 为准。IAM、Console、Ingest 共用 HTTP 装配方式，模块分别拥有路由组、DTO 和生命周期。Ingest 中 `connection/kafka` 负责把安全设置转换成 franz-go 的连接选项，`channel/kafkachannel` 消费外部接入点，`consumer` 消费内部标准 Event，`repository/event` 负责事件存储。[franz-go 客户端选项](https://pkg.go.dev/github.com/twmb/franz-go/pkg/kgo#SASL) · [Gin 中间件作用域](https://gin-gonic.com/en/docs/middleware/using-middleware/)

## 九项整改的交付契约

- 外部 Kafka 读取与平台 Kafka 发布各有连接安全配置。独立解析凭据并在读取配置时校验证书和协议。平台 Kafka 使用首发基线的连接配置；外部 Kafka 使用其独立凭据前缀。
- Kafka 输入仍采用至少一次交付。一次发布返回部分确认时只重试未确认项，发布确认后推进源位移。源记录重读使用包含接入点和 Kafka 坐标的稳定标识，遇到重建主题或改规则后的重放按运行手册处理。
- HTTP 保留 `202` 和响应结构，`accepted` 只计算获得 Kafka 确认的连续前缀。确认受请求期限约束，失败和结果不确定时调用方可重试。事件解析失败的确认目标为解析失败主题。
- 诊断主题默认保存定位和计数所需的最小信息。解析诊断不写设备原文，存储失败记录以源 Kafka 坐标指向已写入的消息。保留期由 Kafka 管理者配置。只在隔离环境演练回放。
- 标准 Event 和诊断记录携带实际运行快照的规则 ID 及修订号。规则更新保留历史修订以便追溯。历史 Event 可缺少这两个可选属性。
- 管理列表由服务端提供有上限的过滤、排序与分页，详情按 ID 获取，规则列表省略定义。保留接入、规则编辑和权限边界。统一文档中的解析规则、字段映射和 Event 存储术语。
- ClickHouse 校验接入 CI，发布流程记载已应用版本及迁移校验依据。恢复演练使用独占库；根入口说明源码启动及 Compose 实际覆盖。
