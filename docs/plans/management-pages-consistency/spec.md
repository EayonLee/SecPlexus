# 管理页一致性与用户列表去重

## 1. 背景

管理区把用户与角色拆成各自页面后，页面各自拼操作区，留下这些问题：

1. **标题不一致**：个人资料页是 `h1 text-2xl font-semibold`，其余管理页各自渲染 `h2 text-base font-medium`。原先统一渲染 `h1` 的容器在去掉标签页时一并丢掉了。
2. **内容宽度偏好失效**：`management.tsx` 外层写死 `mx-auto max-w-6xl`，把全局「内容布局：居中/全宽」偏好覆盖掉了。个人资料页没有这个限制，所以只有它能响应开关。
3. **重复说明文案**：页面、抽屉和表格上方常驻复述标题与字段含义的说明；列表还显示「名称 / N 项」的灰色摘要行。
4. **契约漂移**：IAM 已把 `members → users` 改名（`user_count`、`affected_users`），Web 仍按 `member_count`、`affected_members` 解析，导致角色列表整块触发 `api.protocol_failed`。
5. **用户列表重复行**：一行曾是一个「用户-关系」，同一个人持有多条关系就在同一屏出现多行相同账号。
6. **抽屉形态不统一**：创建角色是右侧抽屉但只有 `sm:max-w-lg`，权限分组被拉成一条窄列；编辑角色抽屉里还塞了「角色用户」列表，与用户管理重复。
7. **列对齐不一致**：同一张表里部分列居中、部分左对齐，阅读时视线来回跳跃。

## 2. 决策

### 2.1 页面标题统一

- 所有页面通过 PageHeader 或 PageTitle 渲染一级标题，字型、字号、行高、字重和字距取控制台工作台。
- 管理列表标题复用左侧菜单的 `Navigation.*` 键。个人资料的主标题显示账号名称，当前面包屑和侧栏入口使用 `Navigation.profile`。四页共用不可点击的「系统设置」面包屑父级；头像菜单和侧栏分组使用同一名称。
- 适用页面：个人资料（`/settings/profile`）、角色与权限（`/settings/roles`）、用户（`/settings/users`）、审计日志（`/settings/audit`）。

### 2.2 页首操作与列表筛选

- 页首展示新建等页面操作。列表内工具条按模板放置查询、筛选与重置控件。
- 工具条由 `components/toolbar.tsx` 统一渲染：`children` 是查询条件，`actions` 靠右成组。各页不再自行拼 flex，按钮位置与尺寸不会各页漂移。
- 页首主操作只出现一次。

### 2.3 宽度交给全局偏好

- `management.tsx` 去掉 `mx-auto max-w-6xl`，与个人资料页统一为 `@container/main flex flex-col gap-4 md:gap-6`。
- 页面自身不再设置 `max-w-*`；「居中/全宽」由此对全部管理页一致生效。

### 2.4 删除重复说明

- 不在页面、抽屉与表格上方常驻解释性文案：标题、字段标签和占位符已表达的内容不再复述。
- 列表不再显示「名称 / N 项」的灰色摘要行：选中对象已由高亮行与页面标题表达。
- 删除说明后首次使用者仍应看出下一步操作与结果；必要的约束与后果提示留在对应控件旁，危险操作（删除、移除）用明确后果的确认框。

### 2.5 Web 契约与 IAM 对齐

- `zApiRole.member_count` → `user_count`；`zApiPreview.affected_members` → `affected_users`。
- 角色页「用户数」列改读 `user_count`；文案键 `memberCount` → `userCount`、`deleteRoleHasMembers` → `deleteRoleHasUsers`。

### 2.6 用户列表按用户聚合

- `GET /api/v1/iam/users` 一行一个用户：身份字段（`id`、`username`、`display_name`、`email`、`status`、`configured`）加该用户直接持有的角色（`roles: [{ id, name }]`）。
- 授权只有「用户 → 角色 → 权限」一条路径，没有中间关系对象，同一用户不会因角色数量重复成多行。
- 列表的 `q` 按用户名前缀或显示名模糊匹配，语义与分页一致。
- 用户投影的 `roles` 字段表示角色分配；持有者数量由角色投影的 `user_count` 提供。

### 2.7 抽屉统一

- `forms.tsx` 的 `FormDialog` 增加 `variant="sheet"`，与对话框共用同一套 RHF 草稿、重新认证与提交路径。
- 抽屉骨架固定为「头部（标题/描述，底边框） + 正文（`flex-1 overflow-y-auto overflow-x-hidden`） + 底栏（按钮右对齐，顶边框）」，只允许纵向滚动。
- 侧向 Sheet 在组件底层读取统一宽度令牌。业务页面使用 SheetPanel，字段按容器宽度排成一列或两列。头部、正文、底栏共享对齐线，关闭后焦点返回触发控件。尺寸见 DESIGN.md。
- 角色权限按资源分组；编辑表单使用纵向滚动和固定操作栏。
- 编辑角色抽屉不再展示「角色用户」：用户归属用户管理，避免同一数据两处维护。
- 删除角色和用户使用 `FormDialog variant="alert"`，带目标名称与不可撤销的后果。

### 2.8 列表页布局文法

- 统一为「`PageHeader`（共享一级标题与页级操作） + 工具条（查询、筛选与重置） + 表格 / 空状态」。
- 搜索框与按钮使用模板紧凑尺寸，小屏允许换行。
- 表格列全部左对齐，表头与单元格同向；状态用徽标表达，不靠居中吸引注意。
- CollectionBoundary 统一决定列表初次加载、失败和刷新失败时的呈现。成功且为空时，按首次使用或筛选无结果提供下一步。重试只重新读取当前数据。业务列表返回 503 时保留会话和导航。

### 2.9 个人资料、用户与角色的模板映射

| 页面 | 模板 | 业务映射 |
| --- | --- | --- |
| 个人资料 | Profile 的页首、线形标签栏及概览 | 头像菜单「系统设置」进入 `/settings/profile`，侧栏和面包屑显示当前页。旧地址 `/settings` 与 `/profile` 分别精确重定向。概览来自 IAM 会话，账号安全放在第二个标签里。时区显式保存，改密成功后退出。 |
| 用户管理 | Users 的同一圆角列表、紧凑页首、身份列及行菜单 | 服务端搜索和分页保留。新增用短弹框，查看和编辑用抽屉。资料、状态、角色分配、密码重置独立提交。 |
| 角色管理 | Roles 的页首创建操作、表格工具栏和行菜单 | 列表按内置及自定义角色分组，展示说明、用户数和权限数，服务端按名称筛选后分页。查看详情包含权限列表；创建与编辑使用抽屉，资料与权限独立保存。保留内置角色和引用限制。 |
| 审计日志 | Tasks 的紧凑工具栏和表格 | 保留操作者、时间、结果筛选和游标分页，窄屏将操作者置于时间下、请求 ID 置于操作名下。 |

短表单用 32rem 弹框。用户和角色的编辑及详情采用 Products 右侧抽屉，最大 32rem，窄于该宽度时占满视口。头部、正文与编辑页脚使用一致边距，正文独立滚动。详情从头部关闭。删除确认使用 shadcn Alert Dialog。IAM 的鉴权、CSRF、服务端校验和查询刷新继续覆盖这些入口。

角色列表沿用有界管理分页。IAM 先使用参数化字面量名称筛选，再按内置状态、名称和 ID 排序分页；总数按同一筛选计算。管理员通常管理数十到数千个角色，模糊匹配会扫描角色目录。查询使用普通读，不新增事务或写锁；请求失败后可以按原查询重试。角色规模明显超出常规管理目录时再依据查询计划评估索引。

## 3. 验收

1. 四页一级标题采用工作台的字体和字号。四个系统设置页的页首和工具条各自遵循对应模板。
2. 「居中/全宽」开关对四个管理页都生效。
3. 页面、抽屉与表格不再出现复述标题/字段的常驻说明，也不再出现「名称 / N 项」摘要行。
4. 打开角色与权限页不再出现 `api.protocol_failed`，「用户数」列有值。
5. 用户列表一行一个用户：同时持有多个角色的用户只出现一行，角色以徽标展示。
6. 用户和角色抽屉遵循同一宽度规则。正文可纵向滚动，长文本换行，按钮可达。
7. 表格列全部左对齐，表头与单元格对齐一致。
8. 单测、类型检查、Lint、构建通过。

## 4. 不做

- 不引入新的筛选系统；审计页仍只有操作者、时间、结果三个条件。
- 工作台与登录页复用统一标题，保留各自业务流程。
- 使用同一份响应式布局验收宽屏和窄屏。

### 模板组件验收

- 系统设置沿用全局明暗色阶与蓝色交互令牌。模板用作页面及控件结构参考。
- Users 采用模板 Card 页首、筛选栏、选择与视图工具栏、身份和状态单元格、共享分页。搜索、角色和状态筛选在同一工具栏中从左向右排列，查询由 IAM 执行。选择和导出限定到本页已获取的用户，表格/卡片切换、隐藏列与分页均有真实交互。
- Roles 采用模板线形标签、分组数据表与共享分页。角色列表工具栏的搜索和类型筛选依次靠左，由 IAM 执行查询。创建角色在同一工具栏靠右，角色通过创建表单提交。权限目录使用本地化资源组名展示真实权限与授权范围。
- Profile 采用模板身份徽标、资料分组和状态侧栏，显示 IAM 提供的资料与会话信息，编辑使用同一组已支持的个人偏好。
- 新增的查询参数均为可选。列表在 PostgreSQL 筛选后分页，沿用稳定顺序、现有角色关联索引和普通只读查询。时间字段来自现有列，无须迁移；失败按既有查询重试。

所有列表使用解析规则的分页组件。已知总数列表在左侧显示总数，右侧显示每页条数、当前页和首／前／后／末页按钮；游标列表显示页次和前后页。筛选器并列展示字段名与当前值。用户列表的选择计数随筛选器放在同一工具栏，有选中项时出现。
