## 1. 实施原则与依赖顺序

这是一次完整交付，下面是任务依赖，不是分批发布承诺。允许实施中的短暂未完成状态，交付结果不得同时保留 Chi/Gin、Authboss/Gin 两套认证编排、两套配置解析或两份契约真源。

```text
T1 基线与能力映射 → T2/D3 HTTP/认证 → T3 Gin 基础 → T4 IAM/Console
                 → T2/D1 契约生成 → T4 生成接入、T7 Web 工程
                 → T2/D2 配置/命令 → T5 根启动与生命周期
                 → T2/D4 Redis/数据 → T4 限流、T6 仓储/迁移
                 → T2/D5 前端组合 → T7 Web 工程
T4 + T5 + T6 + T7 → T8 完整验收、开发范例与治理收敛
```

各门槛只阻止其依赖任务，不把无关能力耦合为总开关。契约方向已选定 OpenAPI 优先，D1 验证 oapi-codegen/Gin 校验和 Hey API 的具体版本组合，不再建设代码优先生成器；未通过前不宣称生成接入/客户端完成。整个交付须完成 D1–D5 及 A1–A12，失败时用证据修订对应方案，不保留替代栈。T8 统一收敛，不拆成多批产品发布。

本次文档批准后按任务推进，不为已批准范围逐项重复询问。若工具无法满足约束、需要改变接口业务语义或扩大范围，先提供证据、修订方案后审核；不通过偷偷加兼容层继续施工。用户本次另行授权全部测试通过后提交、推送并创建 PR；不部署、不执行远程 CI。界面验收按 AGENTS 的专用代理约定执行。

### T2：完成五项能力验证并固定版本组合

验证使用最小代表接口和临时/测试目录；不同时实现完整旧新模块，不留下独立演示服务。保留长期有价值的协议/组件契约测试，其余一次性探索代码在决策后移除。

**D1：OpenAPI → Gin/Go + Web SDK/Zod/Query。** 固定 oapi-codegen、官方 Gin middleware/kin-openapi 以及 Hey API/Zod/Query 的兼容版本；不再以寻找代码优先工具作为项目目标。验证一条代表接口、登录、内部授权、204 和 SSE 的生成及原生接入边界。

| 必验情况 | 验证证据 |
| --- | --- |
| required、optional、nullable、PATCH 缺省/null/零/false | 同一协议生成的 Go/TS/Zod 与真实 Gin 绑定一致，不手补生成结果 |
| `$ref`/组合类型、枚举、Result 泛型或等效响应类型 | required data/code/message/request_id 等约束未丢失；错误响应可消费 |
| UUID、日期时间、字符串形式版本号及大整数边界 | 序列化、校验和前端类型一致，不在 JS 中损失精度 |
| Cookie、CSRF、内部凭证和公开/内部操作 | 文档安全方案/头部及实际保护一致，不把 security 元数据当认证实现 |
| 201、204、404、405、413、415、401/403/503 | 正文、媒体类型、状态、必要头部和错误码正确 |
| SSE、取消及响应开始后的失败 | 文档描述流；生成消费方式不强制 JSON；执行链不缓冲/二次响应 |
| action 元数据、operationId、路由参数 | 可与现有权限目录及 Gin 实际路由检查联动 |
| Gin 接入/strict server/校验组合 | 验证规则真源唯一；使用组件的验证值复用/转换能力，无手写反射或请求体回放 |
| Go 包与生成边界 | 使用官方 import-mapping；公共类型/客户端不导入应用 internal；生成路由与原生 SSE 不重复注册 |
| 公开/内部生成隔离 | 每个操作只有一个协议源；Web 仅消费公开 API，产物不含内部 authorize/服务凭证方案 |
| Web SDK/Zod/Query | SDK 可运行，错误/状态和 schema 相符；Query options 消费 AbortSignal；敏感 key 不包含凭证 |
| 生成稳定性与唯一性 | 同一输入连续生成无差异；Go/TS 编译通过；新增/删除产物受检查，明确消除旧定义 |

## 4. 主要风险与处置

| 风险 | 处置与停止条件 |
| --- | --- |
| 生成/中间件版本不兼容、严格接口不等于完整校验 | D1 验证官方版本组合、验证值复用、包边界和 SDK/schema，不自制生成模板或恢复平行 DTO |
| Gin 绑定默认行为弱于既有请求边界 | T3 测试先明确单 JSON/未知字段/体积等语义，用最小组合补足，不重写校验框架 |
| 移除 Authboss 时遗漏认证行为或重复读取凭证 | D3 验证类型化凭证用例、限流/锁定、版本变化及二次认证；逐项迁移业务断言，禁止请求体回放和恢复旧编排 |
| SCS/CSRF 与 Gin 组合导致提前成功或状态丢失 | D3 验证最终响应所有权与失败路径，通过后迁移；不以“Gin 可包装 http.Handler”作为充分证据 |
| Viper 嵌套环境、空值或类型转换不符合预期 | D2 测真实类型，明确绑定/解码；失败则调整设计，不保留隐式旧加载链 |
| GORM 自动关联/零值省略改变权限与更新语义 | 显式字段、组织条件、事务和版本；真实 PG 验证后替换逐项操作 |
| 框架默认行为改变授权/凭证边界 | D4/D5 验证 Redis 重试/限流、Query 缓存/重试和敏感 mutation；显式配置，不盲目套默认值 |
| 只启用库而未删除旧机制 | 按框架审查表核对采用/替代/保留理由；发现两套同职责引擎不得标记完成 |
| 重构看似通过但删除了安全断言 | 对照原业务不变量和 A1–A12；迁移测试保持行为断言，不靠删除失败测试达标 |
| 文档先宣称新架构，代码仍为旧栈 | 草案保持“待审核”；只有对应实现与证据完成后更新长期规则为现状 |

本地失败通过同分支修复或恢复本次拥有的文件处理，不准备生产双栈/回滚平台。数据恢复沿用既有备份恢复及撤销凭证命令，不执行破坏性恢复演练。用户并行改动必须保留。
