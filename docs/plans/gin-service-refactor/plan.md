# Gin 与全栈框架能力重构实施计划

修订日期：2026-10-29。状态：用户已确认审查方向并要求先整改计划；原生 Gin/配置/导航及无 OpenAPI 收敛已实施；独立审查后的三项缺陷与两项规范收尾已修复，修复后分层回归及 Preview E2E 通过。现有代码、已暂存及未提交改动保留，不暂存、提交、推送或更新 PR。行为以 [Spec](spec.md) 为准，能力取舍见[审查表](framework-capabilities.md)，历史证据见[验收记录](acceptance.md)。

## 1. 实施原则与依赖顺序

采用 [spx-mode](../../../.agents/skills/spx-mode/SKILL.md) 的数据形状、单一职责、先失败测试和先删后加原则。不得把“引入成熟工具”当成增加机制的充分理由；每个组件/配置项先记录当前用途、现有能力不足、删除对象和维护代价，没有实际消费者就不加。

本次是原计划的整改，不是另一个平行方案。以原生 Gin 替换后端生成接入、收敛配置并撤回本地强制 Caddy；已有 GORM/Goose/认证/Query 等有效能力及修复保留。不分批发布，按依赖完成可验证单元：

```text
T1 基线与约束矩阵
  ├─ T2 原生绑定与 Axios/Zod 消费边界 → T3 原生 Gin 与 DTO → T5 Web 消费迁移
  ├─ T4 配置/默认值/三应用启动整改 ────────────────┤
  └─ 已有 F2/F5/F6 修复与 F4 生命周期证据保留 ──────┤
T3 + T4 + T5 → T6 删除与文档收敛 → T7 完整验收
```

计划批准范围内的实现不逐项重复询问；工具不能满足实际协议时先提供证据并修订对应设计，不引入第二个 API 框架/自制生成器。改变产品语义或部署边界需要单独说明，不用历史授权替代当前 Git/部署授权。根 AGENTS、模块说明和贡献指南已同步当前开发路径。

- [x] 固定真实 HTTP 行为与 Web 消费模型；验证 required、枚举、集合唯一/上限、字符串版本、Result、Cookie/CSRF、内部凭证、201/204/405/SSE 和公开/内部隔离。

- [x] 固定最小可用组合及生成范围。Go 与 Web 消费模型的字段边界明确记录，由真实 HTTP/组件测试守住；消费者若依赖该约束，不得发布错误产物或继续堆 schema 补丁。

### T3：原生 Gin、模块 DTO 与规则归属

## 5. 验证入口与执行条件

按 [测试指南](../../testing.md) 使用现有入口，在实现时同步其必要变更，不为了换架构建设另一套 runner：

```sh
pnpm test:unit
pnpm typecheck
pnpm lint
pnpm catalogs:check
make build
go test -race ./src/packages/go/httpx
pnpm test:integration --docker --race
pnpm test:e2e --docker
```

`catalogs:check` 只读核对权限/结果码导出；API 路由和响应由真实 HTTP 测试保护。dev/preview 要证明不安装 Caddy 仍能正常运行；涉及移除的脚本/包名必须更新文档和自动化入口。

`--docker` 只创建隔离测试 PG/Redis，不是应用镜像构建或部署。也可按现有测试指南使用明确专用组件；缺条件时记录未执行，不使用开发数据或 Mock 冒充。Docker 不可用时记录自有残留，恢复后核实所有权再清理，不自动重启/重配用户服务。
