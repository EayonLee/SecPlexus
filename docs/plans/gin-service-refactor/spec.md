# Gin 与全栈框架能力重构

修订日期：2026-10-29。状态：用户已确认原生 Gin、必要自动化和配置收敛的审查方向；原生 Gin 与配置收敛已经实施；用户进一步确认的 OpenAPI/SDK 生成链和集中 contracts 目录移除已完成，本地分层及浏览器验收通过。实现与后续维护以本 Spec 和 [Plan](plan.md) 为准，历史结果见[验收记录](acceptance.md)。

## 1. 需求与目标

使用成熟框架承担通用机制，项目专注业务。采用能力之前必须证明：解决当前什么问题、现有能力为何不足、能删除什么、引入多少配置和维护成本。能推导的值不让用户重复填写，能由现有组件完成的机制不再建设一套。

本次选择原生 Gin 路由、Handler 和模块 Go DTO。Go 类型与 Gin/validator 决定运行时输入行为；Web 使用 Axios、实际消费的 Zod 模型、TanStack Query 与 RHF。删除 OpenAPI/Swag/Hey API 生成链与集中 contracts 目录。删除旧机制必须同步消费者、测试和文档，不留双向生成或长期双栈。

保持已有账号、会话、授权、事务和协议行为；保留 Next.js/React/shadcn、CRM V1 工作台、主题、字体、双语及真实 IAM 页面。不为了更换实现调整业务含义，也不把减少生成文件数量当成目标。

## 2. 重构前问题与采用方案

| 重构前问题 | 采用方案 |
| --- | --- |
| IAM/Console 已用 Gin，但路由接口、Go DTO 和部分响应由 OpenAPI 反向生成 | 用原生 Gin 分组、Handler 和模块 DTO 替换；真实共享类型保持包边界，不导入应用 internal |
| 输入经 OpenAPI middleware、生成绑定和部分 service 重复检查字段约束 | 未知值在 HTTP 边界绑定和结构校验一次；业务状态、授权和事务不变量归用例 |
| Hey API 部分语义需要 patch/resolver；生成结果不天然等价运行时 | 移除生成器，用成熟 Axios/Zod 与真实 HTTP 测试核对协议 |
| 新增 Caddy 后才需要 Web 内部 5174 端口及安装/编排 | 撤回本地强制 Caddy 和双端口，恢复 Next/IAM/Console 三应用源码运行 |
| YAML、Viper SetDefault、根环境示例存在重复默认值；启动脚本覆盖部分监听值 | YAML 拥有稳定默认值，环境提供真实差异，根脚本只推导和注入，不静默重写有效配置 |
| 九项修复部分已有本地代码及历史通过结果，人工验收仍有问题 | 保留证据和修复，不恢复原缺陷；新架构需要重新验收，不搬用旧绿色结论 |

模块现状仍以现有 README 为参考，新方案未实现前不把长期文档写成已经迁移完成。[能力取舍](framework-capabilities.md)区分本次目标与旧版本快照。

## 4. 服务边界与组织方式

```text
浏览器 → Next 同源公开入口（默认本机 5173）
                  ├─ /api/v1/iam/*     → IAM
                  └─ /api/v1/console/* → Console
Console → 独立 TLS + 服务凭证 + 原用户上下文 → /internal/v1/iam/*
```

- 同源入口仅代理固定公开模块，不暴露内部接口、凭证或任意目标。保持 Cookie、Origin/CSRF、真实状态、Allow、Retry-After、多 Set-Cookie、204 和 SSE。
- `cmd` 使用 Cobra；`config` 使用 Viper；`bootstrap` 明确拥有连接/监听及取消；`internal/router` 原生注册；`handler` 处理 HTTP；`service` 持有业务规则及事务；`repository` 负责数据访问。
- Gin Context 不进入用例/仓储；依赖在启动组装，通过显式字段/参数传入，不放 context。共享包只收实际跨应用复用的能力。
- IAM HTTP 模型归 `internal/model`，Console 单一响应归 handler；共享结果/错误码归 `src/packages/go/result`，跨服务授权类型与权限常量归 `src/packages/go/iamclient`，权限业务目录归 IAM `authorization`。Web API/Zod 全部归 Web。不直接绑定 ORM 模型，不机械复制 Entity/DTO/VO/Command，也不为每个函数增加仅转发接口。

## 5. 技术方案与约束

### 5.1 Gin 与成熟认证组件

原生 Gin 注册登录、二次认证、管理、健康检查、内部授权和 Console SSE。公开/内部 Engine 与监听分离，服务凭证不能替代用户身份。按保护边界使用 Group/Use，不用生成 wrapper 承担路由归属。

保留 Argon2id、SCS、gorilla/csrf、账号锁定/失败审计、密码计算并发限制、IP/账号双桶及未知账号替代哈希比较。凭证单次绑定后交具名用例，不编码回 HTTP 重放。会话创建事务重查凭证/账号版本；二次认证不延长原绝对期限。

IAM 的 SCS 提交屏障及补偿只用于真实提交约束，不扩展为全站响应缓冲。成功正文/Cookie 不得早于会话提交；Console SSE 不进入该屏障。内部只读会话策略和既有逻辑空闲/绝对期限保持真实业务语义，不擅改 SCS 默认配置。

### 5.2 绑定、校验和响应

- 用 Gin `ShouldBindJSON`、`ShouldBindQuery`、`ShouldBindUri` 等及其 validator 组合处理 HTTP 输入，避免 MustBind 提前响应。结构约束由一个类型化入口拥有，不再保留相同 OpenAPI schema 与 service 字段校验两份运行时规则。
- 保持一般 JSON 32 KiB、登录/二次认证 2 KiB、明确媒体类型、未知字段拒绝、单 JSON 值、UUID、枚举和整数溢出约束。Gin 默认绑定不保证满足全部规则，先以真实请求验证；缺少能力时只用标准库/正式扩展补一个明确边界，不回退到另一套 API 框架。
- PATCH 保留未提供、空字符串、null、零和 false 的现有含义。邮箱/描述缺省保留、空字符串清空、null 拒绝；不能把普通指针误认为完整三态模型。先验证成熟的可选值表示及原生绑定，不以手写逐字段 map/反射或宽泛自定义解码器解决。
- 创建与更新明确不同字段；组织平台更新与当前组织更新分别限制状态字段；预览用明确的输入形状，非法组合不能靠大量可选值进入业务深处。
- 保留 limit/offset 语义和已确认边界，不因参考项目的 Page/PageSize 更改协议。错误码和权限目录维持唯一业务登记，薄 Result 与错误映射使用真实 HTTP 状态，不暴露 SQL/原始校验值。
- 使用 Gin 原生 Recovery、c.Error/c.Errors、FullPath 和 Writer；保留日志脱敏及关联标识。204 无正文，SSE 直接 Flush/取消；不捕获已编码正文再统一包装。

### 5.3 GORM 使用与数据安全

保留实际使用的泛型查询、类型化投影、显式允许字段、批量关联和 GORM Transaction；保留必要的参数化 SQL/锁、pgx 错误链及 Goose 版本能力。零值、空值、RowsAffected、组织复合键、事务回滚和审计原子性必须保持。不得 AutoMigrate、改写已执行迁移、清库或增加万能仓储；serve 和 status 不隐式 DDL。

授权、委派、最后管理员和版本规则属于业务，不因输入校验或 ORM 自动关联而删除。预览与写入共享实际规则，预览只读，写入在事务中重查当前状态；并发变化可明确版本冲突。

### 5.4 模型归属与最小自动化

后端原生 Gin、DTO、binding/validator、事务是实现真源。Web 的 Axios 负责 HTTP/JSON/超时/取消；拦截器仅适配平台结果、会话及 CSRF。模块 API 明确路径、成功状态与 Zod 消费模型，TS 类型由 Zod 推导，Query/RHF 使用官方原生能力。Go/TS 字段需同步维护，以真实 HTTP、模型边界和 E2E 验证；不再维护 TS-only DTO 或自制 schema/请求引擎。

删除 `src/contracts`、Swag 注释、OpenAPI JSON、Hey API 配置/依赖/生成产物、文档生成步骤及旧导入。内部授权仅由共享 Go iamclient 类型和标准 HTTP/TLS 处理，不进入浏览器。接口文档写在所属模块 README。

仅保留真实跨语言消费的权限和结果码常量导出：`catalogs:generate`/`catalogs:check`，源分别归 IAM authorization 和 Go result，产物清单归 `src/packages/generated-catalogs.json`。这不是新中央契约层。接口变更不要求生成任何路由或 SDK。

### 5.5 路由、权限与安全不变量

保留公开/内部清单、真实状态/必要头、权限目录和服务端保护的对应检查。迁移原生路由后，用实际 Gin Routes、受保护请求和业务访问测试证明，而非保留无消费者的影子路由表。保持跨组织隔离、多角色并集、委派、最近认证、最后管理员、逻辑会话撤销以及故障关闭。

### 5.6 Viper 与环境配置

| 配置内容 | 唯一职责 |
| --- | --- |
| 根 `.env` | 连接/凭证/公开地址等实际环境差异；进程环境覆盖文件，不自动改写私有值 |
| 模块 `config.yaml` | 稳定模块默认值、业务策略和可读结构，作为默认值唯一来源 |
| Viper/mapstructure/validator | 显式环境绑定、类型转换、严格解码与加载校验；不重复登记 YAML 中整套默认值 |
| 根启动 | 加载环境、根据真实模块结果推导地址、筛选后注入并拥有进程，不静默覆盖已生效监听配置 |
| Web | 使用 Next 原生环境；统一启动无需额外维护 `.env.local` |

Go 字段优先级为明确绑定的模块环境 > 适用共享环境 > 模块 YAML。保留真实需要的模块 PG/Redis 覆盖，不机械为每个字段增加用户选项。完整 URL 与分字段优先级、显式空值语义及维护命令的最小前置条件保持清楚；环境只在配置加载时读取。

撤回 `SPX_WEB_INTERNAL_PORT`、默认 5174、Caddy 安装/版本检查/运行配置及相关必选步骤。本地 Next 直接提供浏览器入口；公开端口以 `SPX_PUBLIC_URL` 为单一填写来源，删除重复的 `SPX_WEB_PORT` 配置，绑定 host 与公开 origin 含义不同则保留明确的监听配置。浏览器只使用相对 API 路径。

Next 的上游地址和 Console 的 IAM 内部地址从根启动的真实模块端点推导，不在根示例中重复填写；独立运行/真实远端连接保留所属模块必要覆盖。公开元信息默认复用 `SPX_PUBLIC_URL`，不要求再填相同 NEXT_PUBLIC_APP_URL。TLS、CSRF、内部凭证是当前真实安全需要，不为减少字段删除。

所有已提供非法值在加载时拒绝；serve 专用必需值在日志/PG/Redis/监听创建前验证；端点检查和维护不要求无关 serve 秘密。文件读取/TLS 材料错误保留真实初始化边界。只同步受影响静态配置引用，不扩建部署或兼容旧/新加载器。

### 5.7 范例与长期维护

角色管理作为唯一贯通范例，链接真实 Go DTO、Gin、用例/事务、存储、前端调用、Query/RHF 与测试。实现后同步 AGENTS、贡献指南、配置/测试指南、架构及模块 README；本轮计划文档不提前把现状改成目标。

### 5.8 Redis、命令、生命周期与来源

保留成熟 Redis Store、摘要 key、原子窗口/TTL/429/Retry-After/503 和取消；不自动重试写操作。保留 Cobra 命令及显式维护，HTTP/后台任务用标准 context、errgroup、Shutdown；资源仅由拥有者清理，正常退出不能靠 SIGKILL 证明。

本地 IAM 在 Next 之后看到的是代理来源。原生路由与直接调用仍按 Gin 显式可信代理配置工作，Next 不转发任意浏览器 XFF/Forwarded 来伪装真实 IP。当前不承诺多人公网入口按真实用户来源独立限流；部署时必须另行定义可信入口/多跳边界并做真实双来源验收。这个限制公开记录，不因撤回 Caddy 将它标成已修复，也不因此关闭账号限流/CSRF/授权。

### 5.9 Web 工程能力

Query 拥有可重取服务端数据，RHF 拥有表单生命周期，Zustand 只持有必要内存身份/界面状态。身份范围的唯一切换入口同时取消请求、清理旧投影及安装权威身份；异步解析后的迟到结果仍须隔离。普通同范围刷新不清空所有缓存；密码等凭证不进入 Query/MutationCache、持久化或日志。

二次认证错误密码保持会话与表单并显示可感知、双语的错误；成功切换隔离旧成功/401/503。无效成功响应不能关闭表单或触发 onSuccess；现有组件样式不改，错误反馈复用既有 FieldError/通知能力。

| 编号 | 当前必须达到的行为 | 边界 |

| F1 | 创建/更新及组织权限字段明确；原生 DTO/绑定与服务要求一致，UUID/PATCH 三态正确 | 用原生结构消除重复 wire DTO/规则，不要求生成 Zod 与业务规则完全等价 |

| F7 | 撤回强制入口与双端口，Next 不信任/转发任意来源头，明确代理来源限制 | 公网/多用户真实来源隔离尚未实现，属于部署前置验收，不计入本轮完成声明 |
