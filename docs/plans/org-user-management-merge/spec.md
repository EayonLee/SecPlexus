# 组织/用户管理合并与「成员 → 用户」统一命名

## 1. 背景

上一轮把审计与角色管理简化、设置区收敛到 `/settings` 后，管理区剩余问题：

1. 「全部组织」只展示组织层级树，右侧空白，选中的组织下没有内容。
2. 「组织成员」与「平台成员」是两个页面，语义重叠，用户需要在两个列表里找同一个人。
3. 页面标题缺失或与内容不匹配：个人资料页顶部写「设置」，其他管理页没有标题。
4. 权限分组的标题（审计/成员/组织/角色）字号大于上方的「权限」标题，层级倒挂。
5. 代码、数据库表、权限键、文案里「成员/成员关系」与「用户/账号」两套词混用。

## 2. 决策

### 2.1 组织管理：左树 + 右列表

- 「全部组织」改名「组织管理」。
- 左侧组织层级树（只读导航），右侧展示**选中组织及其全部下级组织**的列表。
- 列表行操作：编辑、删除。创建按钮在顶部。
- 当前组织树已包含全部组织，故右侧为「该组织的子树」而非仅直接子级。

### 2.2 用户管理：左树 + 右列表

- 「组织成员」与「平台成员」合并为一页「用户管理」。
- 左侧组织层级树；右侧是该组织子树下的全部用户。
- **默认选中根组织**，因此默认展示全部用户。
- 顶部搜索：用户名/显示名。
- 创建用户时必须选择所属组织（不因当前选中的树节点而定），默认预填当前选中组织。

### 2.3 成员 → 用户

全量改名，不做兼容：

| 旧 | 新 |
|---|---|
| 表 `iam.memberships` | `iam.organization_users` |
| 表 `iam.membership_roles` | `iam.organization_user_roles` |
| 列 `membership_id` | `organization_user_id` |
| 权限键 `iam.members.read/manage` | `iam.users.read/manage` |
| 路由 `/orgs/:id/members` | `/orgs/:id/users` |
| 代码 `Member*` / `member*` | `User*` / `user*`（组织范围内） |
| 文案「成员」 | 「用户」 |
| 页面 id `members` | `users` |

平台级用户相关键 `iam.platform.users.*` 已存在，保持不变；组织级 `iam.users.*` 与它并存，靠 scope 区分。

### 2.4 UI 修正

- 个人资料页标题「设置」→「个人资料」。
- 每个管理页顶部都有与菜单一致的标题。
- 权限分组标题降级：`FieldLegend` 使用与「权限」同级的字号层级，不再比父标题大。

## 3. 验收

1. 左侧菜单：个人资料 / 角色与权限 / 组织管理 / 用户管理 / 审计日志。
2. 每个页面顶部标题与菜单项一致。
3. 组织管理：左树右列表，列表显示选中组织子树；行内可编辑、删除。
4. 用户管理：左树右列表，默认根组织=全部用户；搜索按用户名/显示名；创建时选组织。
5. 权限勾选区分组标题字号不大于「权限」标题。
6. 数据库无 `memberships`/`membership_roles` 表、无 `membership_id` 列。
7. 代码与文案无「成员」残留（历史迁移文件除外）。
8. 全部测试、类型检查、构建通过。

## 4. 不做

- 不保留旧表名、旧路由、旧权限键或任何映射层。
- 不新增组织级「成员」概念。
