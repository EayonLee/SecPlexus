# 数据接入向导与解析规则编辑器实施计划

状态：已实施。交付目标和页面布局见[设计说明](spec.md)。

## 实施顺序

| 阶段 | 实施内容 | 完成判据 |
| --- | --- | --- |
| 1. 接入草稿与四步向导 | 在现有接入页面重组步骤，保留 RHF 与 Zod 作为表单和提交边界。协议选择进入基本信息，规则选择进入连接与解析。步骤回退保留草稿，最终创建请求仅由确认页触发。 | HTTP、Syslog、Kafka 均能从对应列表入口进入。返回修改协议后，确认页和请求体只含当前协议字段。手工填写的厂商与产品不会被选规则覆盖。 |
| 2. 完成页与详情 | 复用现有接收统计、错误重试、令牌展示及轮换逻辑。创建成功后使用真实接入点 ID 打开结果。一次性令牌仅保留在本次交互内存，沿用现有缓存清理约束。 | 创建后、首次收包后、刷新后、停用后分别显示对应状态。浏览器刷新不重复创建，详情和查询缓存均无法恢复令牌。 |
| 3. 按样本返回提取值 | 在现有试算响应的每个成功预览中增加 `fields` 对象，与现有 `index`、`event`、`partition_key` 一起返回。Ingest 取本次解析后、OCSF 投影前的字段；Web 按样本索引读取。 | 同一样本的提取值与事件来自一次解析。样本顺序、失败序号、命中数及原有响应字段语义一致。真实事件发布格式不受试算响应影响。 |
| 4. 规则编辑工作区 | 改造现有整页编辑器。将选定样本、字段映射行、命中结果和失败原因关联起来。保留 JSON 编辑、已有规则复制、导入导出和只读入口。更新试算失效逻辑及待验证提示。 | 可以从未映射字段建立映射，重新试算后查到同一条样本的源值和输出。失败项可定位，过期结果无法用于保存。 |
| 5. 整体验收与规范 | 将页面到组件的映射补入 Web README，将试算响应补入 Ingest README。按下表验证，再记录实际结果。 | 四服务联调、布局偏好、权限和键盘操作均有验收证据。运行结果与尚存缺口记录在本计划。 |

阶段 3 独立于接入向导；阶段 4 使用阶段 3 的结果。阶段 1 和 2 复用现有创建、读取与统计 API。数据表无需迁移。

## 模板复用与交互验收

按[页面设计映射](spec.md#从-dashboard-模板采用哪些页面设计)落实。工作集中在现有接入页面、规则页面和项目已安装的 shadcn 组件。Invoice 的打印、纸张缩放与拖动排序，Logistics 的地图与示例数据都属于原页面的业务，不进入依赖清单。表单草稿沿用 RHF，列表筛选沿用 URL，服务端试算沿用 TanStack Query 的请求结果。

| 时机 | 组件与状态的归属 | 走查动作 |
| --- | --- | --- |
| 阶段 1 | 协议使用 RadioGroup；规则搜索复用项目 Combobox、ComboboxInput、ComboboxList 和 ComboboxEmpty，由接入表单保存所选规则 ID。 | 键盘切换协议；在规则选择器中搜产品、选规则，再搜一个无匹配名称并按 Esc。已绑定规则、手改来源与返回焦点均正确。 |
| 阶段 2 | 用已有 IngestSection 的标题操作位和 Profile 键值布局承载“修改”“刷新”。当前配置与接收查询分别渲染状态。 | 确认页修改连接后回到原步骤。诊断首次加载失败可重试；已有观测值时刷新失败，仍能读取地址和上次收包时间。 |
| 阶段 4 | 沿用已有 useFieldArray 管映射行，RHF 管草稿，试算响应管样本结果。编辑器仅保存当前样本序号，原文、失败原因、映射值均从同一次试算派生；草稿变更时使旧结果失效。 | 输入两条源值不同的报文并试算，切换样本观察同一行的两个值；再修正目标路径，重新验证前不可保存。窄屏删除或新增行后，焦点回到相邻行或新增目标路径。 |
| 阶段 5 | ListSurface 与 CollectionBoundary 继续管理列表状态，确认可复用的诊断和编辑分区进入 Web 的模板映射说明。 | 以长规则名、失败样本和长 JSON 核对断点。同一页在全宽、居中、窄屏均能完成同样操作。截图成对记录“选择前后”和“修改后待验证／验证完成”，供评审对照。 |

## 接口与状态边界

| 边界 | 实施决定 |
| --- | --- |
| 接入创建 | Web 只在确认页调用一次 `POST /api/v1/ingest/inputs`。提交期间禁用重复操作。遇到明确的校验或重名错误，保留草稿并允许修正。网络中断导致结果不确定时，提供返回列表核对同名记录的入口，防止自动重发。 |
| 接收状态 | 已启用取自 `enabled`。已收到日志取自 Ingest 本进程的 `stats.last_received`、`received`；解析失败使用 `parse_failed`。沿用详情的查询与刷新路径。进程重启后查询到空统计时，文案限定为“本次运行暂无接收记录”。 |
| 试算 | `POST /api/v1/ingest/mappings/validate` 沿用 `ingest.mapping.write`。在现有编译、解析与投影路径中取中间字段，保留字段类型。普通设备接入路径无需保留调试用副本。编译失败展示规则级错误，单条解析失败关联样本索引。提取值仅用于当前授权试算响应；日志、审计摘要和浏览器持久化存储均不记录样本内容。 |
| 权限与入口 | 新建接入点沿用接入点写权限。仅在具备相应读取和试算权限时提供绑定并验证规则的路径。只读角色可以查看已授权数据；所有创建、修改、删除仍由 Ingest 校验 IAM 权限。Console 保持现有职责。 |

实现时从[接入页面](../../../src/apps/web/src/spx/pages/ingest.tsx)、[规则页面](../../../src/apps/web/src/spx/pages/mappings.tsx)、[试算处理器](../../../src/apps/ingest/internal/handler/admin.go)和[归一化逻辑](../../../src/apps/ingest/internal/normalizer/apply.go)入手。共用页面外壳和诊断组件；协议参数及字段映射逻辑留在各自业务页面。

| 真实浏览器联调 | 延伸[现有端到端流程](../../../src/apps/web/tests/e2e/ingest.spec.ts)。创建规则、修改未映射字段、重新验证；绑定至接入点，返回修改来源，确认创建；推送日志后核对收包与 Kafka 事件。复用已有 IAM 会话和 Console 联调。 | 创建前草稿未落库。创建后只发放一次凭证，设备实际推送后页面显示接收记录；只读与通用接入路径可用。 |

## 验收记录

- **接入与诊断。** 隔离 Chromium 流程创建自定义规则和 HTTP 接入点，确认页同时保留规则带入的厂商和操作员填写的产品。使用一次性令牌推送合成日志，在 Kafka 中核对接入点、厂商、产品和事件字段，在 IAM 中核对写入审计。刷新详情后凭证区域消失，收包计数可见。Kafka 向导通过真实生产消息验证消费；只读账号分别在页面和 API 写入边界被拒绝。
- **规则调试。** 同一批次包含两个不同源地址和一条格式错误的报文。切换样本后，源值与投影值都随样本变化，失败项单独展示原因。人工浏览器验证了中文提示及可展开的解析器原文。将已验证的目标路径改为另一路径后，保存动作禁用，重新试算后恢复。JSON 和键值报文均通过试算响应契约测试。
- **页面布局。** 在 2560、1440 和 390 像素视口检查向导的分栏、内容边界与整页溢出。桌面在全宽与居中之间切换并跨页刷新，窄屏规则字段按来源和目标成对排列。人工浏览器另行检查浅色和深色、Syslog 端口错误与回退保留，未写入开发环境业务记录。
- **工程检查。** 根单元测试、类型检查、Docker 集成测试、生产 Web 构建与全栈 Chromium 套件通过。完整浏览器套件 13 项通过。最终调整规则编辑器的对齐和配置收起时机后，接入专项 4 项再次通过。SSE 在测试副本停机后正常结束。Web lint 无错误，仍报告非阻断提示。
