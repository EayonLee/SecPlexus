# 数据接入向导与解析规则编辑器

状态：已批准并实施。本文定义页面行为，[实施计划](plan.md)记录交付顺序与验收方法。

## 两条用户旅程

- 接入设备。操作员从「数据接入」新建接入点，填写实际来源和协议，核对配置，取得设备侧需要的连接信息，最终能判断是否收到设备发来的日志。
- 调试规则。操作员从「解析规则」打开一条规则，用一组样本找出提取失败或映射有误的字段，修改后在同一条样本上复核，再保存。

现有新建页把整个向导限制在约 768 像素。第一屏将通用处理方式和具体规则并列为“日志来源”，第二屏集中填写名称、连接参数和样本。在宽屏上，有限的字段占据左上角，后续需要对照的信息又挤在一列。规则编辑器已有试算、未映射字段和事件预览，当前响应只给出最终事件与失败原因，当前编辑器还把多条样本在同一目标路径上的输出去重后并排显示。两条报文产生不同地址时，操作员能看到两个地址，却无法在该行确认哪个地址属于正在排查的报文。

侧栏提供「数据接入」和「解析规则」两个独立入口。列表筛选、分页，以及新建、编辑和查看详情的现行设计见[规则详情与管理列表](../ingest-rule-field-workflow/spec.md#规则详情与管理列表)。业务范围沿用[接入来源与规则清单](../ingest-source-identity/spec.md)。

## 接入向导

进度依次为「基本信息 → 连接与解析 → 确认配置 → 接入结果」。前三步共用一份当前页面草稿。前两步的主操作“下一步”执行本步校验，第三步的“创建并启用”才写入接入点。第四步对应服务端已创建的记录。

| 步骤 | 页面安排 | 操作与反馈 |
| --- | --- | --- |
| 基本信息 | 桌面左栏填名称，下一行厂商、产品并排；右栏用同一组选项列出 HTTP、Syslog、Kafka，分别说明设备推送、设备转发、平台消费。两栏共同组成首屏，无额外摘要栏。 | 名称和协议必填。保留列表已有的按协议新建入口及预选值。实际来源可留空。 |
| 连接与解析 | 左栏按协议配置连接；右栏选择通用解析或绑定规则。规则选项显示名称、适配厂商、产品与解析类型。选中具体规则后，就地出现样本输入与验证结果。 | 可将适配来源带入尚未填写的厂商、产品，保留操作员明确填写的值。通用解析可直接继续。绑定规则须通过当前规则版本和当前样本的试算。缺少试算权限时，提供可用的通用路径。 |
| 确认配置 | 分两组只读核对“来源与连接”和“日志解析”。每组只列将要生效的值，提供“修改”返回对应步骤。绑定规则显示规则名称、版本和命中样本数。 | 回退保留有效输入。切换协议只提交新协议的参数；更换规则或样本使原试算失效。提交中锁定主按钮，校验或冲突错误定位到可修改的字段。 |
| 接入结果 | 页首显示已创建的接入点，左栏给设备侧操作，右栏使用同一接入点详情中的接收诊断。刷新页面可通过记录地址恢复详情。 | 创建成功时显示配置状态。成功查询且当前进程尚无收包记录时显示“等待首条日志”；收到数据后展示最近收包时间、接收数及解析失败数。查询失败显示重试；已停用的接入点显示实际状态。 |

**协议决定第二步和完成页的内容。**

| 协议 | 创建前 | 创建成功后 |
| --- | --- | --- |
| HTTP | 说明发送方向与令牌发放时机。 | 展示真实接收路径，一次性展示令牌。请求示例使用占位符。关闭凭证视图、刷新或重新进入后，通过已有轮换流程获取新令牌。 |
| Syslog | 输入监听端口，展示实际支持的 UDP/TCP。端口冲突返回连接配置，保留已选规则。 | 展示已配置的端口和发送方式。仅在部署提供实际对外地址时展示主机。 |
| Kafka | 输入 Brokers 与 Topic。服务端按现行配置建立消费者。 | 展示消费目标与接收诊断。只有观察到接收记录后才更新收包状态。 |

已创建接入点继续从详情的“编辑配置”修改名称、来源与绑定规则，通过原有确认操作启停或轮换令牌。协议与连接参数按现行修改契约呈现。接入结果和日后查看详情共用同一组诊断组件，避免两处解释同一状态时出现偏差。

## 规则编辑与验证

页首沿用工作台标题规格，主操作为新建或保存。桌面正文并列两个工作区，左侧“规则与样本”，右侧“字段映射”。窄屏按相同顺序纵排。新建时展开名称、适配厂商、产品与格式；打开已有规则时将元信息收成一行摘要，可展开编辑，优先给样本和字段留空间。

1. **选样本。** 编辑器支持多条样本，沿用每次最多 50 条的限制。结果按提交时的样本序号关联。选择某条样本时，原文、对应字段及事件预览同步切换。单条失败展示该样本和失败原因，成功样本仍可查看。
2. **改映射。** 从左栏样本区选择本次试算的一条报文，右栏标题显示样本序号及结果。主体表格按“源字段、提取值、OCSF 目标路径、输出值”排列。示例：源字段 `src` 提取到 `192.0.2.7`，映射至 `src_endpoint.ip`，同一行可核对该路径的实际输出。缺失值、空字符串、数字零和布尔假分别呈现。未映射字段可直接加入草稿，焦点移至待填写的目标路径。
3. **看结果。** “验证样本”调用 Ingest 实际解析器。汇总显示命中数和失败数，完整 OCSF 事件按需展开。修改映射或样本后清楚显示待重新验证，只有本次草稿所有样本命中才能保存。请求迟到的旧结果不得覆盖较新的草稿。
4. **保存或复制。** 编辑字段和编辑 JSON 使用同一份规则定义，来回切换保留可表达的设置；复杂定义沿用 JSON 入口。内置规则只读，有权限时可复制为自定义规则。导入先生成草稿，试算通过后才能保存。保存失败保留输入；有未保存修改时，主动离开编辑器提供放弃确认。

本次仅在试算接口增加按样本返回的提取值。接入点沿用既有创建即启用行为，数据结构和权限沿用现行契约。高级字段转换、实时抓包、节点调度和存储路由属于独立的后端能力。

## 页面与组件约定

- 标题、步骤条、正文分隔线与操作区对齐同一内容边界。内容边界由控制台的全宽或居中偏好决定；字段各自控制行长。全宽模式允许样本和长路径使用剩余空间。
- 根据正文容器的可用宽度折叠为单栏。长 JSON、路径和列表只在各自的阅读区换行或滚动。步骤进度、行级错误和当前样本均有文字及可访问名称；键盘可切换协议、选择样本、返回修改并提交。字段错误聚焦首个待修项。
- 系统界面文字同步提供中文与英文。主题、标题字重、焦点样式与间距遵循[项目设计规范](../../../DESIGN.md#console-content-width)。截图验收使用合成数据。

### 三个值得按真实操作走查的画面

**接入第一步。** 从模板布局设置中三个并列选项的做法取其可扫描性。协议有三个固定值，在桌面用一组等宽可点击的单选项呈现：HTTP「设备推送」、Syslog「设备转发」、Kafka「平台消费」。名称、厂商和产品占另一列。协议字样为主，方向为次；整项均可点，箭头键可移动。侧栏展开、正文变窄时，选项组整体移到来源下方。步骤条仍是顺序导航，只有已完成的步骤可回访。模板的全局偏好组件与业务表单各自保存自己的值。

**规则编辑。** 页首保留保存和取消。左栏从上至下为规则配置摘要、样本输入和试算动作；右栏标题对齐左栏标题，其下为当前样本的字段表。源字段与目标路径用等宽字体，标签用项目正文，失败文字紧邻受影响的字段或样本。宽屏共用“源字段／提取值／目标路径／输出值”列头，窄屏只保留一个紧凑的样本选择器，放在结果上方，每项映射拆成“来源与值”“目标与输出”两行。遇到 50 条样本，左栏样本索引区局部滚动，右栏只呈现当前样本。选到失败样本时，该位置展示对应原因，并清除上一条样本的输出。完整事件从右栏末尾展开。切换样本不会丢失映射草稿或再次发起试算。

**结果与诊断。** 参考 Logistics 把对象标识、状态和异常放在对应详情中的做法。HTTP 创建成功时，一次性凭证和复制动作留在设备配置区域；诊断区显示该接入点的接收时间与计数。一次刷新失败时在诊断区给出重试，配置区仍可使用。已有数据再次获取失败时保留上一次的观测值，并标明刷新失败。停用、尚无观测、解析失败各有文字，只有真实异常使用告警色。浅色和深色使用同一组语义令牌。

## 设计依据

某安全产品的操作流程体现了两个可复用的做法：接入提交前按配置分组核对；规则编辑时让每个字段的匹配值与映射设置相邻。SecPlexus 结合已有协议、OCSF 输出和模板组件实现这两个交互。

- Google Security Operations 支持修改原始样本、预览标准事件并验证解析器。这里采用“选定样本 → 核对字段值 → 保存”的顺序。[自定义解析器](https://docs.cloud.google.com/chronicle/docs/event-processing/configure-custom-parsers)
- Graylog 在接入诊断中分别展示输入状态、流量与消息错误。这里用已有的收包时间和失败计数区分配置成功、等待数据和解析异常。[接入诊断](https://go2docs.graylog.org/current/getting_in_log_data/input_diagnosis.htm)
- Microsoft Sentinel 的连接器按采集方式引导配置，并单独验证日志到达。这里将设备侧下一步与接收结果放在创建后的同一页。[连接器配置与验证](https://learn.microsoft.com/en-us/azure/sentinel/connect-cef-syslog-ama)
