# 控制台数据接入重构实施计划

状态：已实施并完成联调与浏览器验收。

## 实施顺序

| 顺序 | 改动 | 验证 |
| --- | --- | --- |
| 1 | 先为控制台菜单、旧书签、仅接入点可读、仅映射可读和无权限直达补有针对性的失败断言。在 Web 主壳接入权限可见性，加入模块路由与按权限显示的独立侧栏分组，移除设置列表的接入项。 | 延用现有 IAM 角色与浏览器会话夹具。在设置、工作台、接入列表和详情之间访问，核对菜单当前项、直接访问结果和登录回跳。 |
| 2 | 以现有 shadcn Table、输入框、Select、DropdownMenu、Empty 和 PageHeader 组装接入点列表。先为查询过滤组合、无统计显示和权限下的映射名称回落写失败用例。调整已有输入查询的使用方式，详情按标识从清单取当前接入点。 | 单测验证显示逻辑。真实浏览器检查搜索及回退保持、状态与接收时间分别显示、停用后仍可查看已有统计。 |
| 3 | 重写创建页的流程编排，保留现有 Zod、RHF、TanStack Query 和同源 API。先替换既有向导 E2E 的入口和顺序断言并观察失败。创建结果携带的凭证只在当前页面交互中暂存，禁止进入地址、持久化状态及查询缓存。 | 延用 HTTP 推送到 Kafka 的浏览器用例，增加对新诊断页的首包断言。Kafka 配置用例延伸至实际消费与页面回显。Syslog 用真实日志完成浏览器验收，协议与分帧继续由现有集成用例覆盖。用原会话夹具验证无映射权限时可通用接入。 |
| 4 | 将详情分为基本信息、连接配置、解析规则和接收诊断，配置修改从详情明确进入和提交。用现有删除与轮换确认组件，保留服务端拒绝结果。稳定处理 loading、失败、无记录、已接收、停用及无对应接入点。 | 真实浏览器验证查看诊断、修改或停用、轮换后新旧令牌的实际行为。确认 Kafka 输出仍在已有端到端测试中被验证。 |
| 5 | 将映射抽屉改为整页编辑器。复用现有试算请求和预览组件，调整配置区、字段表与样本区位置。对映射版本或样本修改后的试算失效先验证，再改实现。 | 编辑、复制、只读与引用阻止删除延用已有覆盖。更新一个核心浏览器流程，验证样本失败后修复和归一化字段。 |
| 6 | 更新 Web、Ingest README 及行为 Spec 的导航索引。运行本地单测、类型检查、构建、隔离集成和 E2E，之后在浏览器逐页观察并修正视觉问题。验证通过后，用根启动入口重启当前开发服务并检查就绪。 | 记录命令结果、视口、语言、主题和实际失败项。根启动继续读取当前私有配置。 |

## 功能与组件边界

- Web 负责导航、表单、确认、页面状态和已获授权数据的呈现。路由与数据权限直接取现有 IAM 目录。同源入口继续将管理请求交给 Ingest。Console 业务 API 保持原有职责。
- 传输、写操作、试算和审计复用现有 HTTP 契约及服务行为。现有统计字段来自当前进程，详情不将它们推算为历史窗口、成功发布数量或通道健康度。设备地址使用现有连接契约；页面没有设备侧入口配置时，引导用户使用部署端点及可复制的相对路径。
- 页面栅格沿用现有内容宽度与间距。列表紧凑，新建操作在页首，查询条件放在列表工具条，名称和最近接收在窄屏仍可查阅。详情使用内容栅格，窄屏纵排。映射编辑器需要长内容阅读空间，原始 JSON 和样本各自可滚动且不撑宽整页。

## 列表与导航组件

独立入口复用现有权限目录。输入列表按所选规则展示引用，行菜单直接打开编辑状态；规则页提供来源筛选、名称搜索、引用跳转和分页。查询和分页参数随详情链接传递。审计、IAM、接入及工作台共用分页控件，审计保留游标语义。搜索、选项、日期及页码控件和静态检查见 Web README。验收覆盖菜单权限、规则到接入点的完整路径，以及打开弹层后用键盘选择和提交真实查询。

来源属性与规则筛选见[接入来源与规则清单](../ingest-source-identity/spec.md)。现有列表接口返回整组记录，列表分页发生在浏览器。本次未验证数千条规则下的响应时间。批量启停限当前页，逐项发送目标状态；成功项从选择中移除，失败保留供重试。

规则表的可选列按共享列表容器的宽度显示。侧栏和用户布局偏好会改变可用宽度，浏览器验收以操作列完整可见、整页无横向溢出为准。编辑器使用服务端返回的 OCSF 事件展示逐字段输出，未映射字段可加入草稿后重新试算。

## 测试与现场验收

参照[改动类型与必需测试层](../../development/testing.md#改动类型与必需测试层)。显示、过滤、样本结果失效用单元测试。导航、权限和创建用现有隔离 E2E。已由 Ingest 集成套件覆盖的设备鉴权、分流、重投、审计和存储契约继续运行。若实施确需改变 HTTP 路由或权限语义，先补真实服务和数据库的允许与拒绝集成用例。

```sh
make test
make typecheck
make build
make integration ARGS="--docker"
make test-e2e ARGS="--docker"
```

浏览器人工验收用隔离栈，包含典型桌面、窄桌面和移动侧栏，覆盖中文、英文、浅色、深色与键盘操作。依次检查空列表入口、首条日志、失败样本提示和恢复、只读页面、无权限直达、成功保存后的回退以及令牌轮换确认。以已有数据和 API 响应交叉检查结果，修正后重验。浏览器操作按 AGENTS.md 使用专用 Computer Use 子代理。

## 验收记录

- 浏览器验证了两个侧栏入口、深链高亮、两个列表翻页、规则来源筛选、从引用数到接入点编辑及返回。审计结果弹层支持键盘选择、Escape 和焦点恢复，日期选择与清除生效。窄屏规则表优先保留名称、来源、引用与行操作，两类列表共用长名称截断。
- 使用业务页违规示例复验 Biome，原生表格、按钮、输入框、文本域和下拉框均报告错误。直接引入 NativeSelect、InputGroup 或独立分页也会在 CI 的 Web lint 阶段失败。

- Web 76 项单测通过。类型检查、三项 Go 服务和 Next.js 生产构建通过。隔离 PostgreSQL、Redis、Kafka 集成套件通过。
- 13 项真实浏览器 E2E 通过，包括 HTTP 推送的 Kafka 输出、令牌轮换、Kafka 入站首包、只读用户深链与拒绝写入，以及在接入点和 IAM 用户管理页跨路由切换布局并刷新。Console SSE 及日志凭据排除检查通过。
- 分类栏展开时，1440 像素窗口内规则表可用宽度和实际内容宽度均为 882 像素。390 像素窗口内两者均为 356 像素，行操作可见。已在真实浏览器验证厂商到产品的筛选、OCSF 路径筛选、当前页选择和批量停用确认。
- 浏览器手工验证测试规则样本、通用解析回退、映射复制及编辑、完整事件展开、列表筛选、操作确认、旧书签和接入点诊断。向 Syslog 输入发送两条真实 UDP 报文，接收计数为 2，解析失败计数为 1。
- 侧栏展开时，1440 像素视口中全宽与居中表格分别约为 1114 与 1021 像素，1920 像素视口中约为 1577 与 1209 像素。390 像素宽度下，中英文及明暗模式可完整查看收包时间并打开行操作。列表与两栏编辑器已按实图复核。
- 私有配置与根示例均有 44 个键。使用根 preview 命令重新启动四服务，三个后端就绪接口、Web 同源 IAM、已登录接入点与映射页面/API 均返回 200，验证会话退出返回 204。
