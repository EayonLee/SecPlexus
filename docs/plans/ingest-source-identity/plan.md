# 实施与验收

1. 修复空端口生成可复制地址的问题，移除规则分类、对应查询状态、字段索引及专用文案。桌面和窄窗口都能从规则名称、来源、格式找到规则。
2. 调整接入详情和编辑流程，使用一致的页面底色、字段对齐与诊断区域。缺少端口时明确显示未配置，复制仅对有效地址开放。
3. 以向前迁移在接入点和规则表分别保存 vendor 和 product。管理 API 和新建、编辑分别传输。首次执行时先删除接入点，再删除自定义规则，保留内置规则及审计记录。再次启动应保留新配置。
4. 接入运行时按当前注册表读取来源，随各协议的接收记录进入事件元数据。保持原有 OCSF 产品和规则映射的优先级。样本试算和未绑定规则的接入均可正常工作。
5. 真实 PostgreSQL 验证迁移前后、一次性清理、局部更新和运行时读回。共用隔离浏览器流程验证创建、编辑、设备推送与 Kafka 事件。人工验收覆盖明暗、宽窄、字段缺失与返回路径。

## 验收结果

- 在隔离 PostgreSQL 上从旧配置升级，验证旧接入点和自定义规则被清理、内置规则可编译、重复启动保留新配置。局部更新与令牌轮换在同一次数据库更新中完成。
- HTTP 推送实测将接入点自己的厂商和产品写入 Kafka 事件。已有 Syslog TCP 连接及 Kafka 消费组经注册表刷新后，新事件采用修改后的来源。
- 四服务浏览器套件 13 项通过，覆盖录入、样本验证、字段/JSON 编辑切换、收包、令牌轮换、权限、审计、布局偏好以及跨页面导航。
- 真实浏览器检查 390、1440 和 1920 像素视口。1440 和 1920 的接入列表同时展示厂商与产品，390 仍能打开详情和操作菜单。明暗主题均已核对，临时数据已清理。
