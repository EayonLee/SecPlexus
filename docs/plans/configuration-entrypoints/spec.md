# 配置入口一致性

根启动、独立进程、Compose 和测试工具各自执行其配置职责。配置项在入口间保持相同的含义，并在使用前校验。

| 入口 | 行为 |
|---|---|
| 根配置 | 进程环境优先于根 dotenv，显式空值保留。缺少管理员密码时拒绝初始化和启动。Kafka SASL 引用的值只注入 Ingest。 |
| Go 服务 | `SPX_<APP>_BIND_HOST` 控制监听地址，`SPX_<APP>_HOST` 是调用地址，共用同一个端口。Ingest 预检校验 PostgreSQL 连接格式、必需的 IAM 凭证和可用的 TLS 证书。启用 Ingest 原生 TLS 时，就绪探测和同源上游使用 HTTPS 并校验服务器证书。 |
| Compose | 可以独立启动 PostgreSQL、Redis。全栈 Compose 提供 IAM、Console 和 Web。IAM 迁移和服务读取相同的账号配置，跨容器使用实际监听和容器服务名。需要完整 Ingest 服务时使用源码或独立部署入口。 |
| Web | 在运行时解析 Ingest 上游。Web 保留现有 IAM、Console 和 Ingest 同源路径，以及原认证边界。未配置 Ingest 的部署可启动 Web，访问 Ingest 时收到不可用状态。 |
| 归档 | 根入口复用 Ingest 环境。支持离线检查、迁移、结构检查和运行。配置了归档时，常规离线预检也发现无效的归档配置。归档仍独立运行。 |
| 数据库检查与测试 | 进程环境优先于根 dotenv。sqlc 仅需测试 PostgreSQL，使用独立数据库和临时配置。ClickHouse 备份开关从根配置传入外部集成测试。 |

原有数据表、消息主题、认证决策与归档投递语义保持既定契约。启动配置只在进程启动时读取，Web 每次请求复用已解析的上游。资源占用和锁路径与现有服务、迁移和消费者相同。检查在连接、迁移或启动之前报告不可用配置。归档和 SQL 检查失败时沿用现有消费位移与临时数据库回收机制。
