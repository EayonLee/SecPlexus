# 审计与角色管理简化、设置区合并 — 需求与方案

## 1. 背景

当前 IAM 管理区存在四处被用户明确指出的过度设计：

1. 审计日志分成「组织审计」和「平台审计」两个入口、两个页面、两个标签，查同一张 `iam.audit_events` 表，只是过滤条件不同。
2. 角色与权限页顶部有列不下的角色标签；创建角色走模态框，需要手填「角色标识」；列表展示「类型」；查看与编辑分离成两个入口。
3. 角色的 `code`（角色标识）与 `kind`（类型）对使用者没有实际价值，却牵连数据库约束、内置角色识别与「组织必须保留至少一个管理员」这条不变量。
4. 顶栏头像菜单里「个人中心」与「系统管理」是两个并列入口，左侧菜单再拆「个人资料 / 账号安全」两项，属于同一件事的重复入口。

本需求的目标是**减少概念数量**：删掉分支、删掉标签、删掉用户无法理解的字段，把同一件事收敛成一套实现。不做任何历史兼容。

## 2. 决策

### 2.1 审计：单一列表

- 删除「组织审计」「平台审计」两个导航项，合并为一个「审计日志」。
- 删除顶部「组织审计 / 平台审计」标签，替换为搜索条件：**操作者、时间范围、结果**。
- 后端合并为单一端点，授权在服务端判定：具备平台审计权限者可看全部；仅有组织审计权限者只能看自己可见组织范围。
- `org_id IS NULL` 的平台级事件对拥有平台审计权限者可见。

**理由**：审计的事件模型（`action`、`actor`、`outcome`、`org_id`）本就统一；分页只是过滤条件不同，拆成两个入口没有边界收益。参考 GitLab（`/audit_events` 单一流 + scope 过滤）、Keycloak（Events 单页 + 筛选器）的做法。

### 2.2 角色：删除 code 与 kind

- 数据库删除 `iam.roles.code`、`iam.roles.kind` 两列，以及依赖它们的 CHECK 约束、`UNIQUE(org_id,code)`。
- 角色只用 `id`（UUID）关联；名称、说明、权限即全部可编辑属性。
- 删除内置角色概念：不再有 `org_admin` / `member` 系统角色，组织创建时不再自动铸角色。
- 删除「组织必须保留至少一个管理员」不变量（含 `ProtectOrganizationAdministrators`、`ProtectAdministeredOrganizations`、`OrganizationsWithoutAdministrator` 及启动告警）。管理员能力改由**自定义角色 + 相应权限**达成。
- 保留「平台必须至少一个有效超级管理员」（`ProtectPlatformAdministrator`），它与组织无关，是平台级安全底线。

**这是本需求唯一削弱既有保证的改动，必须明示**：此前任一组织缺管理员会被兜底保护；删除后，若某组织的自定义角色被清空或成员被全部移除，该组织将暂时无人能管理，直到超级管理员介入。用户已确认接受——超级管理员始终是最终兜底，组织级强制管理员属于过度设计。

### 2.3 角色列表与抽屉

- 删除顶部角色标签区。
- 搜索条件（名称）+ 功能按钮（创建角色）**同一行**：搜索靠左，按钮靠右。
- 列表列：名称、说明、成员数、操作。删除「角色标识」「类型」两列。
- 「查看」改为「编辑」，与创建共用右侧抽屉（shadcn `Sheet`）。
- 创建抽屉：角色名称、角色说明、角色权限（创建时即选择权限）。
- 编辑抽屉三段式，从上到下：**角色信息**（可改）、**角色权限**（可改）、**角色成员**（只读）。
- 删除角色前必须判断该角色下是否有绑定成员；有则禁止删除并给出明确原因。

### 2.4 Settings 合并

- 头像菜单「个人中心」「系统管理」合并为一项：英文 `Settings`，中文「设置」。
- 左侧菜单合并「个人资料 / 账号安全」为**一项**并置于首位，其后是角色与权限、组织、审计等。
- 路由收敛：`/settings/profile` 与 `/settings/account` 合并为单一 `/settings`。
- 管理区路由由 `/management/**` 迁入 `/settings/**` 之下，形成单一入口。

## 3. 行为契约

| 项 | 契约 |
|---|---|
| 审计列表 | `GET /api/v1/iam/audit-events?actor=&from=&to=&outcome=&limit=&offset=`；服务端按调用者权限裁剪可见范围 |
| 审计权限 | 平台审计权限 → 全部；组织审计权限 → 仅 `org_id` 在其可见组织内的事件 |
| 角色创建 | `POST /api/v1/iam/roles`，body 仅 `name`、`description`、`permissions`；`id` 由服务端生成 |
| 角色更新 | `PATCH /api/v1/iam/roles/:id`，body `name`、`description`、`version` |
| 角色权限 | `PUT /api/v1/iam/roles/:id/permissions`，body `permissions`、`version` |
| 角色删除 | `DELETE /api/v1/iam/roles/:id?version=`；`member_count > 0` 时返回冲突并说明原因 |
| 超管保护 | 平台最后一名有效超级管理员不可停用或降权 |
| 路由 | 管理区统一在 `/settings` 之下，无 `/management` 前缀 |
| i18n | `en` / `zh-CN` 目录键完全对齐，无孤立键 |

## 4. 验收

1. 审计页只有一个入口、一个列表，顶部是操作者/时间范围/结果三个筛选条件，无「组织审计/平台审计」标签。
2. 角色页顶部无角色标签；搜索与「创建角色」按钮同一行，左对齐/右对齐。
3. 角色列表展示名称、说明、成员数；无「角色标识」「类型」列。
4. 创建角色为右侧抽屉，含名称、说明、权限三项，创建即选权限。
5. 编辑角色为右侧抽屉，三段式：信息可改、权限可改、成员只读。
6. 删除有绑定成员的角色被拒绝，并显示原因。
7. 头像菜单只有一项 `Settings`；左侧菜单第一项为设置，其后为角色、组织、审计。
8. `/settings` 单一路由；旧 `/settings/profile`、`/settings/account`、`/management/**` 不再存在。
9. 数据库无 `iam.roles.code`、`iam.roles.kind` 列。
10. 迁移 Down 可回滚（或明确拒绝并说明）。
11. 文档、README、索引、i18n、路由常量全部同步，无残留引用。

## 5. 不做

- 不保留任何旧路由重定向、旧字段兼容、双写或过渡层。
- 不新增组织级管理员强制机制。
- 不改动审计事件本身的表结构与写入路径。
