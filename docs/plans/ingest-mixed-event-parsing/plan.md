# 混合日志实施计划

旧契约和多行合并的后续处理见 [解析规则清理](../ingest-rule-cleanup/plan.md)。

1. 在真实处理入口验证同一来源的流量、认证失败、部分解析和未分类结果。
2. 保留 v1 规则和存量事件，增加 v2 分支判定和版本化字段目录，再接入管理面和模板。
3. 归档端先兼容两个契约版本，按前向迁移升级列结构，再开放新写入。回退时保留能读取新数据的消费者。
4. 在同一测试接入点对照试算、Kafka 与 ClickHouse，复验隔离数据库、三协议、权限、主题切换及归档回读。容量单独实测。

## 页面线框

| 页面 | 宽内容区 | 窄内容区 |
|---|---|---|
| 新建接入点 | 页首 → 四步进度 → 左侧当前表单与右侧实时摘要 → 操作 | 步骤、表单、摘要和操作纵向排列 |
| 规则工作区 | 页首与操作 → 左侧定义和分支 → 右侧样本、结果与字段对照 | 规则配置、样本、结果顺序排列 |
| 列表与详情 | Products 工具栏、记录表、分页。详情用字段分组与接收诊断 | 工具栏折行，保留名称和操作，字段组单列 |

组件对照使用 Dashboard 的 Products 列表、Product Form 字段分组、Add Product Drawer 固定操作区。页首和响应式内容框由平台现有组件提供。

## 数据与发布顺序

1. ClickHouse 先应用 00002，校验账本及列结构，再启动同时读取两个契约的消费者。
2. 使用独立的 Ingest `serve` 替换写入实例。此时已有绑定保留 v1 行为。
3. 全部写入实例就绪后应用 PostgreSQL 00007，开放新模板并发布 Web。先迁移消费者再启用新写入。
4. 上线前记录接入点绑定与 Kafka 位移。回退窗口内保持双版本归档能力，暂停或恢复明确的接入点配置。归档结构与已有 Event 保留。

## 容量测量

Apple M1 Pro 上用同一组 CEF 混合样本各跑三轮基准。单规则为每条 7.85–8.26 µs，约 5,208 B 分配。混合规则为 7.41–8.36 µs，约 5,275 B 分配。两者均为 80 次分配，测量包含匹配、转换和完整 Event JSON 构造。该结果不包含 Kafka 确认、ClickHouse 延迟和资源长稳，生产持续 50,000 EPS 仍待专用环境实测。
