## 1. 目标和现状

为Web、IAM、Console建立一套可维护的账号、组织、登录和接口认证能力。全部页面融合到现有Web；IAM拥有身份与授权，Console拥有业务资源。

立项时IAM/Console为骨架、Web使用模板Mock；本次已实现真实服务、迁移和管理页面。以下验收按当前实际接口执行，不以模板Mock作为交付证据。

本次收敛依据：用户要求不做安装流程，默认超级管理员、组织管理员、普通成员三类基础身份；同时首版必须支持组织内自定义角色与权限编辑，不预置审计员、安全分析师等业务角色。避免无用扩展，不得把简化理解为砍掉可编辑授权模型。公开技术依据与设计取舍见Plan。

## 2. 首版范围

- 自动建表、初始化默认组织与首位超级管理员；直接进入登录页，没有安装向导、公开bootstrap接口或“第一个注册者成为管理员”。
- 用户名/密码登录；管理员创建账号与分配组织；用户改密，超级管理员重置密码；启用、停用、角色变更。
- 服务端Session、退出/全部退出、设备会话撤销、空闲/绝对过期；Console复用统一鉴权。
- 三类基础身份、组织内自定义角色/多角色绑定/权限编辑、组织数据隔离、跨模块审计、配置、前端缓存和故障行为。
- 现有Arco页面基线保持不变，只接入真实认证与必要管理页。

首版不建设：Owner、角色继承、显式deny规则、任意策略脚本、部门/用户组产品、公开自助注册、邮件邀请/邮箱验证/邮件找回、SMTP/outbox、MFA、SSO、SCIM、Passkey、服务账号/API Key产品、通用策略引擎、数据库业务配置中心。上述能力没有预建表、预留端点或承诺排期；以后有明确业务需求再单独设计。内部服务访问IAM的认证是当前必需的基础链路，保留。

超级管理员是用户全局标识；组织管理员和普通成员由组织内系统角色/成员关系表达。自定义角色是组织内权限集合，成员可以绑定多个角色；超级管理员不能通过普通角色编辑/绑定接口授予。系统角色仅保留org_admin和member，业务角色由用户创建，不按角色名硬编码授权。

## 3. 角色与边界

| 角色 | 定义 | 可管理范围 |
|---|---|---|
| 超级管理员 `super_admin` | 平台全局角色，users.is_super_admin=true派生 | 平台用户、组织、组织管理员、全平台组织业务；读取/操作仍明确目标org_id并审计，不允许无范围查询 |
| 组织管理员 `org_admin` | 绑定受保护系统角色org_admin | 本组织业务、普通成员创建/移除、自定义角色及权限分配；不能授予超级管理员或组织管理员，不能改全局账号状态/密码 |
| 普通成员 `member` | 默认绑定系统角色member，可另加自定义角色 | 默认仅本人资料/密码/组织入口；业务动作由自定义角色授权，不自动赋予业务read/write/export/execute权限 |

普通成员是组织身份，不是固定只读/读写权限包。权限由模块声明的稳定action目录提供，用户组合成审计员、安全分析师等角色；多角色取允许权限并集，不引入隐式deny。默认member没有业务读取、修改、执行或导出权限，避免审计员因基础角色而意外获得写权限。高危操作必须持有对应action、满足近期认证和业务审批，不能靠角色名放行；管理员也不绕过审批。

授权规则只有一套：有效身份+有效组织/成员+当前数据库角色权限+真实资源归属/状态。平台动作不要求org_id，只允许受保护超级管理员；组织动作必须明确org_id，超级管理员获得指定组织范围，其他用户按有效成员/grants求值；中央求值先检查已知action及安全门禁。删除最后一个业务角色后业务权限归零，不回退硬编码默认角色；角色改名不影响授权。同组织绑定用复合外键强制，跨组织自定义角色完全隔离；列表/统计/导出/批量/任务/SSE都不能绕过。

自定义角色支持创建、编辑、停用、成员分配、删除前影响统计和有效权限预览。org_admin由目录种子显式持有全部当前有效organization权限；可委派权限为操作者有效权限与目录delegable集合的交集。系统角色不可编辑/删除或清空grants；org_admin只能由超级管理员授予，普通自定义角色不能复制其受保护身份能力。组织管理员能组合并授出自己可委派的组织权限；被委派的角色管理员也必须受同一上限约束。未知权限、平台权限和未实现的数据范围一律拒绝；新增权限默认不进入已有自定义角色。

首版数据范围是组织级，不假称已实现对象ACL/字段脱敏/ABAC；统一Authorize接口仍保留真实资源类型与ID输入、结构化范围输出，业务仓储强制应用org_id。以后增加对象范围/用户组时扩展中央求值与仓储适配，不让每个API重新按角色判断。

新组织在创建事务中指定有效组织管理员。默认组织的首位超级管理员同时具有org_admin成员及角色绑定记录。不得禁用/降权最后一位有效超级管理员；不得移除、禁用或降权活跃组织的最后一位有效组织管理员（按当前有效系统角色绑定计算）。超级管理员也不能通过全局禁用用户绕过后者，需先移交或停用相关组织。

## 4. 行为契约

### 4.1 自动初始化

- 应用按连接配置使用已提供的PG/Redis，不要求Docker；make dev不调用Docker；需要部署基础组件时使用独立Compose入口。后端落地后由受控迁移/种子完成库表及默认组织/管理员初始化。再次启动不清库、不重置密码、不重复创建。
- 默认管理员 admin/secplexus，可用环境变量覆盖，仅空账号库初始化。登录成功后按实际权限进入业务。
- 生产PG可由Compose初始化创建数据库，也可连接运维预建库。建库属于部署层，迁移属于模块，serve不持有CREATEDB/DDL权限。
- 首次无超级管理员且账号表为空时才初始化；凭证缺失则明确失败，不开放安装页面补救。不为空却没有有效超级管理员属于数据异常，不自动提权已有用户。
- 并发迁移/初始化有PG锁；任何一步失败不就绪，事务回滚后可重试。初始化后无需继续提供初始密码。

### 4.2 账号与密码

- 本版采用用户名登录，邮箱仅为可选联系信息，不依赖邮件服务。用户不能自行选择注册角色；登录页注册入口改为联系管理员。
- 超级管理员可创建用户、维护组织成员及管理员；组织操作者（组织管理员或被授予iam.members.manage的成员）只可创建全新普通账号并加入本组织；是否允许操作取决于对应action，而非显示角色名。已有账号跨组织加入、全局账号修改由超级管理员处理，避免组织管理员凭用户名接管其他组织身份。
管理员设置密码并安全交付用户，只存哈希；创建和重置后可直接登录，不另设临时有效期。
- 密码8～128个Unicode字符，校验请求字节上限和哈希资源。旧密码验证、更新、认证版本递增、会话撤销和审计有明确事务边界。
- 仅超级管理员可重置其他用户全局密码；本人改密验证旧密码。任何改密/重置都撤销全部旧Session，重新登录；不自动接续新登录。
- 登录统一无效凭证响应，账号/IP限流与短期锁定；恢复后可重试。密码验证时携带auth_version快照，最终建会话再次比较；并发重置/停用后旧登录不能成功。

### 4.3 Session与全平台认证

- 单一服务端Session体系，浏览器只持HttpOnly Cookie，不存JWT/refresh token；生产Secure、Host-only、SameSite=Lax。
- 建议默认空闲30分钟、绝对8小时。首版采用标准请求访问续空闲期限，**包括后台轮询**；不再做前台活动识别或专门activity接口。轮询不能延长8小时绝对期限。
- 只在登录/重新认证等必要场景轮换；轮换使用新逻辑会话并撤销旧记录，重新认证继承原绝对期限。完整重新登录才能开始新的绝对期限。
- 用户退出、改密、停用、管理员撤销后下一次鉴权失败。SCS并发写回即使残留旧存储行，也不能让已撤销的逻辑会话重新有效。
- IAM与Console的所有Cookie写请求均校验CSRF/Origin。Console通过受保护内部authorize接口交IAM验证原请求上下文；不信任浏览器X-User-ID/角色/组织声明。
- 组织从业务URL显式提供，不修改全局“当前组织Session”；两个组织标签页互不影响。超级管理员跨组织访问也须明确org_id及真实资源归属。
- 401表示无有效身份，403表示权限不足或需要先改密，503表示依赖故障，429表示限流。依赖故障不降级放行，也不当作正常退出。
- 已执行的业务不能倒退撤销；高危动作提交/执行前再检查身份权限。异步任务记录发起者/执行者，不保存Cookie；SSE建立时及每30秒复查身份。

### 4.4 前端、角色编辑与配置

- 头像下拉提供单一管理中心入口及本人资料、密码、会话和退出；业务侧栏仅保留业务菜单，管理中心内部侧栏分组织与访问、平台管理、系统设置；设置区复用AppShell及左侧栏容器，仅切换菜单树，支持返回业务。平台/组织/个人页面不能混用数据作用域。
- 页面首次加载先确认真实身份；未知态不闪现管理员页面。导航隐藏不能替代后端校验。
- 页面、菜单、按钮共享一份能力投影及声明式页面清单；导航先过滤子页再裁空分组，只读自定义角色按action访问设置，不强制要求org_admin身份。对象动作仍以业务后端判断为准。
- 角色编辑器按模块/资源/动作展示权限目录，区分业务读取、修改、执行、导出与授权管理；影响人数、有效权限预览由后端计算，不能只隐藏按钮。角色名称/说明可编辑，但不允许用户造出没有后端实现的权限动作。
- 继续使用现有Axios/Redux管理认证状态，不为首版强制引入另一套状态管理库。用户/组织/权限摘要只存内存；保留非敏感UI偏好与“记住用户名”。
- 退出/账号切换时取消请求、递增本地认证epoch并清除用户相关缓存；组织请求绑定org_id，旧响应不能污染新组织。跨标签退出用BroadcastChannel通知后再向服务端确认。
- 公共API固定/api/v1/{module}，内部/internal/v1/{module}；模块路径不做环境变量。配置遵循AGENTS.md的模块/能力命名规则。
- 每个模块独立维护配置，config.yaml中声明环境变量及默认值，环境值优先；根目录是统一启动配置，启动时必须检查存在，缺失则生成并提示检查，不成为模块依赖，用户按需增加模块已支持的高级环境变量。
- 首版安全时长/限流阈值来自类型化部署配置；不为此建安全策略表或设置管理页面。同一字段只保留一个配置来源，修改明确要求重启；以后实际需要UI编辑再设计持久化。
- 审计覆盖初始化、登录结果、密码、账号状态、组织/成员/角色、会话撤销；不记原始认证材料。安全变更与审计同事务，失败不能返回成功。

## 5. 验收标准

| ID | 通过标准 |
|---|---|
| AC-01 | 依赖可由外部提供或显式使用Compose；后端初始化完成后有默认组织/admin和必要表；无需安装页面；重复/并发启动不重复创建或重置；缺初始Secret/迁移失败不就绪 |
| AC-02 | 迁移、运行、维护使用同一账号，账号具备本项目迁移权限；外部PG不被stop停止；停止保留卷；初始密码不在仓库/日志/命令参数中 |
| AC-03 | 基础身份与自定义角色在后端有效；org_admin无法提权/停用全局用户/重置他人密码/接管已有账号；未知角色/权限拒绝；默认member无业务read/write/export/execute权限，保留明确本人服务及组织入口 |
| AC-04 | 最后一位超级管理员/活跃组织管理员保护覆盖并发、全局禁用、成员移除/降权；系统角色不可被自定义角色改名/复制绕过 |
| AC-05 | 正确凭证登录；失败/未知账号统一响应；限流及锁定可恢复；新账号和密码重置后直接按实际权限访问；主动改密撤销旧会话 |
| AC-06 | 真实时钟/受控测试验证idle与absolute；轮询能续idle但不能续absolute；登录轮换，旧逻辑会话不可用 |
| AC-07 | 两IAM副本下退出/全部退出/停用/改密立即影响后续鉴权；旧SCS写回不能恢复身份；重置期间旧密码登录不能建有效Session |
| AC-08 | IAM/Console Cookie写请求缺CSRF/Origin不匹配失败；伪造身份头、非法return_to、跨组织资源ID与批量接口均拒绝 |
| AC-09 | Web→Console→IAM真实链路通过；401/403/503区别展示；账号/组织切换、跨标签退出与迟到响应不串缓存；认证Mock不匹配真实路径 |
| AC-10 | 审计提交失败安全变更回滚；PG/IAM故障503；Redis故障时依赖限流的登录写接口503，不切本地空限流放行 |
| AC-11 | 配置类型/未知字段/环境占位均校验；不同平台使用独立Redis库，同平台副本共享限流；API前缀和生成客户端一致 |
| AC-12 | 真实PG迁移锁/失败恢复/备份恢复通过；恢复后撤销旧Session；SSE撤权30秒内断流，高危执行再次校验；不把Mock验证当完整交付 |
| AC-13 | 用户自建审计员只有选定读取权限；分析师只有所选业务动作；角色改名不改变权限；删光绑定后不回退默认权限；两角色并集和跨组织隔离均正确；系统角色清空拒绝、自定义角色清空成功后业务权限归零 |
| AC-14 | 角色编辑/授权与审计同事务、版本冲突409；并发撤权/转授不越权；两副本下一次鉴权读到变更；新权限不自动赋给旧自定义角色；在用角色删除409并提示影响成员 |
| AC-15 | 齿轮管理中心按可见子页显示，内部组织/平台/系统分区正确，头像显示本人服务；设置区侧栏替换/返回/刷新/组织切换正确；只读审计员不见用户管理但可进入审计，无权深链403，不留空管理分组 |
| AC-16 | action目录、生成常量、路由/页面元数据一致；业务接口不按角色名称判断；功能授权结果不能当作对象ACL最终授权，未知scope拒绝，权限概要与安全概览不泄密 |

三类基础身份、自定义业务角色及取消安装流程按本次用户要求收敛；用户名登录、管理员发放密码按已确认的简化策略实施。未要求的扩展不进入首版验收。测试分层按[测试指南](../../testing.md)，不将临时排障或工单复现堆入集成/E2E套件。

验收范围说明：Console当前仅组织上下文与SSE；批量、导出、后台任务及高危业务执行尚无对应产品功能，其要求作为后续接入约束。当前高危IAM管理写操作已在事务内复核。v1不声称提供对象ACL或历史版本滚动升级。
