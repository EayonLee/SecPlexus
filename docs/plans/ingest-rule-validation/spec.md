# 解析规则基础字段校验

状态：已实施，验证结果见[实施计划](plan.md)。

## 改造范围

新建、编辑和复制规则共用以下规则。名称仍用于人工查找，接入点引用仍使用规则 ID。厂商与产品描述适用范围，多个规则可以适用于同一个产品。描述用于说明场景及边界。

| 字段 | 值与长度 | 查重 |
| --- | --- | --- |
| 规则名称 `name` | 必填。单行，去除首尾空白后 1–100 个 Unicode 码点。 | 所有规则，包括内置规则，共用现有不区分大小写的唯一性约束。编辑时保留本条原名称可以通过。 |
| 数据源厂商 `vendor` | 必填。单行，去除首尾空白后 1–120 个码点。 | 允许重复。 |
| 数据源产品 `product` | 必填。单行，去除首尾空白后 1–120 个码点。 | 允许重复。 |
| 规则描述 `definition.description` | 必填。多行，统一换行并去除首尾空白后 1–1,000 个码点。 | 允许重复。 |

单行字段接受各语言文本、普通空格、数字和标点，例如「边界防火墙 / 华东（备用）」和 `Palo Alto Networks`。拒绝换行和控制字符。描述接受换行及制表符，拒绝其余控制字符。字段以文本展示，前后端使用相同的空白规则、计数方式与边界用例。100 和 120 延用 Ingest 的现有边界，1,000 与 IAM 角色描述一致。

## 错误如何显示

- 点击「提取字段」或保存时检查全部基础字段，聚焦第一处错误。仅浏览控件或移出焦点时，空字段保持普通状态。必填缺失、长度超限和字符无效都显示在对应控件下方。
- 客户端在已有错误的字段发生修改时重新校验。为错误文本设置 ID，输入控件用 `aria-invalid` 和 `aria-describedby` 关联。保留模板的控件、栅格和分组，长度和原因写进错误消息。
- 保存遇到重名时，回到基础配置，提示「规则名称已存在，请换一个名称」，定位名称并保留样本、字段映射和其他草稿。只修改规则名称时，已有样本结果仍对应同一规则内容，可直接返回保存。
- 修订冲突在当前页面提示，避免覆盖他人的修改。连接失败、权限变化和无法定位到字段的错误放在现有表单层反馈区。页面用中英文消息目录解释稳定错误码。
