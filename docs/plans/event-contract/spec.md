# SecPlexus 标准事件契约

Event 规范和所有权已确认，当前 ClickHouse 存储与查询见[事件存储](storage.md)。这里的 Event 指接入后供检测、检索和分析使用的一条标准化安全记录。事件产生告警的条件、告警聚合和案件状态由各自业务定义。

现行平台契约为 `v1`，字段以锁定的 OCSF 1.10.0 为准。多类日志、异常 Event 和验收出口按[首次发行基线](../first-release-baseline/spec.md)执行。

## 核心实体与代码边界

| 对象 | 语义和归属 | 权威存储 |
|---|---|---|
| Event | 一次已通过契约校验的安全观测，独立于是否产生告警。Ingest 拥有标准化、发布和存储。一条已接入的厂商告警也先成为保留来源身份的 Event。 | ClickHouse 的 `spx.events`；Kafka 用于传输和重放。 |
| Alert | 一项需运营的安全发现。规划中的 correlator 拥有生成、合并和告警业务状态。一个 Alert 可引用多条 Event，一条 Event 可支持不同规则的多个 Alert。 | 拟使用 PostgreSQL，待该模块立项。 |

**未来扩展边界。** 如后续立项，correlator 可以消费已发布的 Event，并通过事件 ID、发生时间和类别引用证据。Alert 的字段、状态机、存储、API 和部署在该需求启动时确定。本期交付边界是 Event 发布、归档及回查。

**权威定义跟随领域所有者，公共包负责分发。** 模块内维护可跨语言读取的 JSON；确有多个代码消费者时，将同版本派生的消费类型与枚举发布到 `src/packages/` 的相应语言包，CI 通过重新生成检查漂移。模块私有仓储类型、ClickHouse 行结构、HTTP DTO、告警转换策略仍归各自模块。Web 通过拥有者的授权 API 发现运行中的字段与枚举。后台消费方构建时绑定已发布契约，消费消息时按版本解释。Alert 运行时目录在确有界面需要时由 correlator 暴露。

预览和实时接入共同使用 `normalizer.Result` 保存候选字段、未映射项和折算警告。`pipeline.Event` 持有消息正文和发布元数据，标准流正文为校验通过的根级 OCSF JSON。诊断消息经同一发布器发送到独立主题。字段定义仍由 JSON 契约拥有，跨模块的强类型消费代码在出现实际消费者时从同版契约派生。[归一化实现](../../../src/apps/ingest/internal/normalizer/apply.go) · [事件发布](../../../src/apps/ingest/internal/pipeline/pipeline.go) · [ClickHouse 存储设计](storage.md)

## 标准及所有权

首版平台契约的目标基线为 OCSF 1.10.0。平台选择支持的事件类、对象和扩展，沿用上游英文路径、类型、枚举编码与语义。每个已支持的类满足所选版本的必填字段和条件约束。首条验证链路采用已有 FortiGate 流量样本对应的 Network Activity。版本化规则产出的标准事件标记 1.10.0。存量规则切换前需逐项核对实际输出与消费者支持范围。[OCSF 版本文件](https://github.com/ocsf/ocsf-schema/blob/1.10/version.json) · [网络活动定义](https://github.com/ocsf/ocsf-schema/blob/1.10/events/network/network_activity.json) · [现有事件组装](../../../src/apps/ingest/internal/pipeline/pipeline.go)

**Ingest 拥有标准事件契约，唯一权威定义放在 `src/apps/ingest/schema/events/`，以 JSON 随代码版本管理。** 清单锁定 OCSF 版本、提交、支持的事件类及平台契约版本。同目录保存构建所需的上游定义、许可证和平台扩展。解析继承及对象引用后形成按事件类查询的字段目录。上游标准字段保留原有英文路径与枚举编号。[官方字段字典](https://github.com/ocsf/ocsf-schema/blob/1.10/dictionary.json)

| 使用方 | 获取方式与职责 |
|---|---|
| Ingest | 在拥有 JSON 的 Go 包中用 `go:embed` 内嵌文件，启动时加载目录。无法解析引用、路径或枚举冲突时启动失败。规则编译、样本预览与事件发布共享加载结果。 |
| Web | 通过同源 Ingest API 按类获取字段；模块 API 使用 Axios 和 Zod，字段详情同时返回 en、zh-CN 的字段和枚举名称。TanStack Query 按目录修订、平台契约版本及类别缓存。Web 按 next-intl 的当前语言选择返回的名称，按钮等界面文案仍来自 Web 消息目录。标准路径始终可见。 |
| 告警、降噪和分析模块 | 构建时从指定版本的 JSON 派生所需的类型与枚举，随各自服务发布。消费事件时读取契约版本，选择已支持的解释方式；遇到未知版本，记录可诊断原因并隔离该记录。消费热路径无需请求 Ingest，也无需导入 Ingest 的 `internal` 包。 |
| PostgreSQL | 保存用户规则、源到目标的映射、厂商取值转换和规则绑定的契约版本。字段目录的发布、变更和回退通过版本库管理。 |
| 模型工具及评测 | 从同版目录导出实际涉及的事件类、字段释义与枚举。脱敏样本和评测记录标注平台契约版本，生成的结构化记录经过同一套字段校验。 |

## 从规则到可持久化的 Event

| 边界 | 输入和输出 | 谁决定字段值 |
|---|---|---|
| 解析、归一化 | 厂商报文 → 源字段 → `normalizer.Result` | 用户选择目标类、该类允许映射的字段、取值和转换。预览可返回未完成的映射及逐字段诊断。 |
| 构造 Event | 归一化结果和接入上下文 → 已校验的 Event 或失败原因 | 平台写入事件 UID、接收时间、契约版本和来源身份，根据已选类及活动计算派生标识。保存与导入规则均检查目标路径，包括常量和整个父对象，避免覆盖保留字段。 |
| 发布与存储 | Event → Kafka value → ClickHouse 类型列和正文 | 对外 JSON 的 `time`、`class_uid`、`src_endpoint`、`metadata` 等位于根级。字段目录决定这些属性的形状。`Fields`、`Warnings` 属于归一化处理过程。归档从一条已发布消息提取列并保留其完整正文。 |
| 下游分析 | 发布版本及事件字段 → 检测条件、证据或分析输入 | 以类和字段含义解释数据，按目录解释枚举。平台扩展也须随版本声明对象结构、基数和类型，并限制原文及未映射内容的保留。 |

例如，规则将 CEF 的 `src` 映射为 `src_endpoint.ip`。预览显示提取值及 IP 校验结果，发布正文使用嵌套对象 `src_endpoint`，写入时派生 `src_ip` 类型列。另一来源的等价映射可复用同一个检测条件。Web 根据目录区分可映射、平台写入和派生字段，服务端执行相同约束。

## Ingest 字段查询接口

两条 GET 路由均注册到 Ingest 的 `internal/router`，使用用户会话与现有 `ingest.mapping.read` 权限，并遵循平台统一响应格式。[现有映射路由](../../../src/apps/ingest/internal/router/routes.go)

| 路径 | 成功响应的 data 内容 |
|---|---|
| `GET /api/v1/ingest/event-schema` | 当前 `contract_version`、`ocsf_version`、`catalog_revision`（含语言资源的目录修订）及支持的事件类列表，每类提供 `class_uid` 和名称。 |
| `GET /api/v1/ingest/event-schema/classes/{class_uid}` | 相同的契约版本、OCSF 版本、目录修订、类别标识及继承展开后的字段列表。每个字段提供路径、含义、逻辑和序列化类型、基数、必填条件和值的归属（可映射、平台写入、派生）。返回字段的双语名称与释义，有枚举时按适用范围返回编码及双语标签，有单位时随字段返回。 |

首版接口提供当前发布目录。无会话返回 401、缺少读取权限返回 403、合法但未支持的类别返回 404。编辑器用类详情中的版本提交规则；服务端发现版本不受支持时明确报错。发布记录中 `metadata.version` 标明 OCSF 版本，`metadata.spx.contract_version` 标明平台契约版本，规则自身的修订号保留独立含义。

## 字段语义和边界

字段详情按契约版本和事件类展开继承、对象、已启用的 profile 与平台扩展。以下信息在授权目录 API 和 Web 字段详情均可查，模型字典从同一目录导出。

| 查询项 | 要求 |
|---|---|
| 英文路径与中文展示名 | 保留完整可复制的标准路径，如 `src_endpoint.ip`。中文名区分源与目的、编码与标签；可用路径或中文展示名查找。 |
| 业务含义 | 说明观测对象、方向与取值语义；有单位或使用限制时一并展示。中文名和业务解释分别维护。 |
| 逻辑类型与基数 | 同时给出标准逻辑类型和 JSON 表示；明确单值或数组，数组说明元素类型。解析嵌套路径时保留各级对象或数组的上下文。 |
| 必填条件 | 标明当前类与 profile 中的必填、推荐或可选，另外展示适用的条件、关联字段及父对象存在条件。将会改变记录有效性的条件同时纳入后端校验。 |
| 枚举值及其含义 | 返回该类支持的完整编码集合，每项分别给出英文标签、中文展示名与业务解释。非枚举字段标明不适用；缺失、Unknown 和 Other 各有语义。 |

以 `severity_id` 为例，中文展示名为“严重度编码”，表示归一化后的事件严重程度，逻辑类型为 `integer_t`，JSON 表示为单个整数，在 Base Event 中必填。编码 `4 / High / 高` 表示需要立即处理；`0 / Unknown / 未知` 表示严重度未知；`99 / Other / 其他` 表示来源级别未映射到标准级别，此时 `severity` 必须保存来源的级别标签。上述三项是示例，目录须返回该类有效的全部枚举。活动编码 `activity_id` 还须结合事件类解释。[OCSF 字典](https://github.com/ocsf/ocsf-schema/blob/1.10/dictionary.json) · [Base Event](https://github.com/ocsf/ocsf-schema/blob/1.10/events/base_event.json)

接入点、规则版本及解析来源等平台信息使用受控扩展，并显式区分 OCSF 版本与 SecPlexus 契约版本。规则作者可定义源字段和转换方式。标准字段之外的厂商信息可按策略脱敏保存到扩展或未映射区。无法分类或不符合该类必填约束的报文进入可诊断的非标准记录路径，仍可追溯原文；标准事件消费方仅接收通过校验的记录。

## 验收

- 真实 Kafka → ClickHouse 可回查同一 Event，同一已发布消息重放时，精确查询计数仍为一。无告警的 Event 也可检索。用两个不同事件的 ID、发生时间和类别分别回查完整正文。
- 两个不同来源的网络样本能映射为相同语义的源 IP，使用同一条匹配条件命中。
- 保存和导入规则时均拒绝拼错的目标路径、不可用的事件类别和非法的枚举映射。实际发布前能识别非法 IP、错误类型及缺失的必填对象。
- 未分类报文不会被计入 API Activity。严重度 Other 不会因编码为 99 而命中高危条件。
- 模型获得该类的字段说明、枚举释义及经过脱敏的样本；评测覆盖源与目的方向、Unknown 与 Other、缺失值。模型生成的结构化事件或规则接受同样的契约校验。
