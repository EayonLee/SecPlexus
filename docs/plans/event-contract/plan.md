## 实施与验收状态

按下方七个阶段的完成条件核对。阶段关闭需要代码与对应层级的验收证据。

| 阶段 | 当前可核实的交付 | 关闭该阶段还需要 |
| --- | --- | --- |
| 1. 核对现有数据 | 已核对旧版输出、诊断流和平台保留字段。隔离 PostgreSQL 中用测试规则生成根级正文，覆盖有无端口、源与目的地址、毫秒时间、来源与等级。开发库预检无在用的旧版自定义规则，本地重启后就绪。 | 通过实际接入协议和 Kafka 验收内置规则。发布时记录目标 Kafka 的分区切换位移。 |
| 2. 建立权威目录 | OCSF 1.10.0 快照和双语清单已内嵌，可离线加载。现有测试覆盖继承字段、数组、字段值域和类专属枚举。 | 补齐目录变更的独立回归证据，覆盖版本差异、枚举语义变化、本地化修订和无效引用。 |
| 3. 接通目录 API | 两条只读路由使用 `ingest.mapping.read`。全栈用例已验证授权读取、未登录 401、未知类别 404。当前 IAM 的已认证用户默认拥有映射读取，未新增仅供测试的角色行为。 | 按完成条件独立核对完整字段语义。路由层验证 IAM 返回拒绝时的 403。 |
| 4. 统一规则和事件校验 | 保存、预览和运行时加载均拒绝缺少 `contract_version` 的规则。单测覆盖非法 IP、端口溢出、未知目标、非法活动编码及 Other 缺少原始级别名称。使用真实 Kafka 验证样本预览后实际推送的源 IP 和非法事件分流。 | 在实际切换时记录在用规则版本和分区位移。 |
| 5. 接通 Web 编辑器 | 浏览器验证 JSON 草稿切换和文件导入、目录断线重试、按中文搜索字段、核对枚举与条件说明、键盘绑定规则、样本预览、新建及重新打开后修改保存。后端测试覆盖非法目标与枚举。 | 主要编辑与保存操作已验收。 |
| 6. 验证 Event 存储 | 已实现独立消费、类型列和根级正文写入、确认后位移提交、隔离及周期漂移校验。真实 Kafka 与隔离 ClickHouse 验证首版建表、写失败后的恢复和重放、精确回查、COMMENT 与 TTL 漂移、过期清理及窗口内迟到事件。 | 迁移校验和、上一版本升级、备份恢复、确认结果不确定的故障注入、代表性查询和积压容量。 |
| 7. 验证 Event 可消费性 | 隔离事件存储用例验证两种来源可用同一源 IP 检索，回读保留 Other 编码和名称、NULL、零端口和毫秒时间戳。未知版本记录稳定原因与 Kafka 坐标，保留窗口内用坐标回查。 | 从真实接入协议贯穿两个来源至归档查询，发布脱敏事件样本与版本说明供其他模块复用。 |

**性能验收仍开放。** HTTP 并发与入站字节上限、Syslog 连接回收、流水线排空期限及 Kafka 拉取分批已实现。剩余事项包括发布正文及客户端缓冲上限、Kafka 部分确认重试和混合报文持续 50,000 EPS、恢复及积压追赶。以专项计划的验收条件为准。[性能与容量计划](performance.md)

### 最新验证

- Ingest 竞态测试与真实 PostgreSQL 仓储集成通过。Web 类型检查通过，单测 22 个文件、77 个用例通过。Web lint 通过，仍有现存告警。容量压测须使用专用环境。
- 使用已配置的 PostgreSQL、Redis 与 Kafka，`ingest.spec.ts` 四条浏览器用例通过，覆盖 JSON 导入、枚举与条件说明、样本验证、目录断线重试、复开并保存规则、HTTP 接入、Kafka 接入向导和实际收包、只读访问边界、全宽与居中布局跨页保留。全栈启动验证 Ingest 服务凭证可读取 IAM 的权限目录。[浏览器用例](../../../src/apps/web/tests/e2e/ingest.spec.ts)
- 以隔离 ClickHouse 26.8.47.5 联调真实 Kafka。数据库拒绝写入时消费位移保持未提交，恢复后原组提交正确的下一位移。另一组重复消费后仍可按证据键准确回读。手工修改保留天数或列注释均被识别。归档进程需由有目标 ClickHouse 的部署环境单独启用。[归档集成用例](../../../src/apps/ingest/internal/consumer/worker_integration_test.go)

## 实施前确认的差距

| 优先级 | 现状及影响 | 实施前固定的验收用例 |
|---|---|---|
| 高 | 启动装配只给 Kafka 发布器传了失败 topic。`pipeline.Options` 缺少相同参数，失败标记依赖该参数，发布器又按标记选 topic。现有死信单测手动赋值，绕过了实际装配。 | 从正常启动入口发送一条有效记录和一条解析失败记录，以各自标识验证两个 topic 的归属。失败类型由流水线判定，topic 名由发布器配置一次。标准与诊断 topic 配成同名时拒绝启动。 |
| 高 | 通用分类回退为 `6003`，组装器沿用规则预填的 `metadata.uid` 和 `metadata.version`。这会影响分类、消息身份和写入时的版本解释。 | 无规则、无法分类、报文截断、篡改平台保留路径分别有可诊断结果。标准记录的正文 UID 与发布 ID 一致。规则编译覆盖常量、直接映射及父对象赋值。 |
| 中 | 采集源可能只提供地址，也可能同时提供端口。ClickHouse 投影保留端口。 | 以含端口与缺端口两种样本验证提取、整数转换、范围及 NULL。用已知发生时间的样本核对时间单位，区分来源厂商、产品和平台处理组件。 |

## 性能与资源预算

阶段 1 先登记协议占比、峰值字节率及基准。优先补齐 Syslog 已接纳连接回收、HTTP 和 Kafka 在途内存预算、发布排空期限，再比较阶段 4 增加契约校验前后的分配和延迟。阶段 6 在真实 Kafka 与隔离 ClickHouse 上验收批量写、在线查询、重放及积压追赶。每项的源码证据、验证负载和通过条件见[性能与容量验收](performance.md)。

## 实施顺序

| 顺序 | 实施内容 | 完成条件 |
|---|---|---|
| 1. 核对现有数据 | 从代表性测试规则、样本、预览及实际发布 JSON 出发，逐项核对 OCSF 1.10.0 Network Activity 的必填项、类型、枚举与厂商元数据。列出无规则、映射失败及未知类别当前发往的 topic。核查规则版本现有存储方式，列出所需的配置变更或迁移及影响范围。 | 形成现有输出与目标契约的差异表。明确已有规则的切换方式与标准流、诊断流的边界，再变更存储或运行行为。 |
| 2. 建立权威目录 | 在 `src/apps/ingest/schema/events/` 落地锁定的上游来源、JSON 清单、所需类与对象、许可证及平台扩展。用同目录 Go 包内嵌定义，生成可按类查询的字段目录。 | 离线构建及启动可用；单测覆盖嵌套路径、对象继承、数组、条件必填和类别专属枚举。无效引用及冲突得到明确报错。检查中英文标签覆盖、版本差异、枚举码重用和投影引用；只改中文名也能刷新目录缓存。 |
| 3. 接通目录 API | 在 Ingest 定义模块 DTO 和两条只读路由，复用映射读取权限与既有错误响应，更新 Ingest README。 | 真实路由测试覆盖授权、未登录、越权、不支持的类；逐类遍历目录，核对版本、英文路径、中文名、业务释义、类型、单值或数组、条件和完整枚举解释。以锁定上游类与字典做独立对照，覆盖类专属活动编码、非枚举字段、数组元素与条件必填。 |
| 4. 统一规则和事件校验 | 规则保存、导入、样本预览复用同一规则编译入口。按字段类型转换厂商值，校验真实记录，成功后标注版本并发布。对无法分类或违反必填约束的数据复用失败记录处理路径，纠正 `6003` 通用兜底语义。 | 对同一份样本，预览映射与实际 Kafka 记录的业务字段一致；用 `severity_id=99` 且缺少来源级别标签的样本验证条件必填错误；另一条实时样本包含非法 IP 时，诊断可定位字段，标准 topic 中没有该条无效事件。 |
| 5. 接通 Web 编辑器 | 复用 Web 现有 Ingest API、查询缓存及 shadcn 选择器。先选类，再搜索目标字段；源字段和值转换仍可配置。样本面板按行显示提取值、转换结果和错误。 | 浏览器验证新建、编辑、导入、预览、保存、重新打开，覆盖未知目标、非法枚举，以及目录加载失败后的重试。用英文路径和中文名定位同一字段，打开详情核对枚举释义和必填条件。 |
| 6. 验证 Event 存储 | 依照 [ClickHouse 表设计](storage.md) 实施模块专属迁移与独立事件写入消费组。写入类型列和不可变事件正文，成功后提交位移；记录消费进度、积压和写入错误。 | 真实 Kafka 与测试 ClickHouse 验证列映射、缺失值、宕机重放后的精确计数、保留期及按证据回查。记录典型查询的扫描量和延迟。空库安装与上版升级均对照投影，另在隔离库验证手动 ALTER 得到有定位信息的漂移报告。发布前后和周期巡检使用同一结构比较逻辑，见[漂移控制](storage.md#字段与数据库漂移控制)。 |
| 7. 验证 Event 可消费性 | 通过脱敏契约样本和事件回查核对逻辑类型、枚举与可重放版本。真实跨模块 Go 消费者出现时，再评审共享类型的生成与项目规则。 | 两种来源的同一标准 IP 可用同一条件查询；等级 99 保留 Other 语义；归档能区分不支持的版本。以 Event 契约和回读证据完成验收。 |

**切换与回归。** 先记录当前 topic 分区位移、在用规则与消费组，准备能识别目标版本的消费者，再启用新生产者。明确事件写入首个可接受位移，避免把旧版积压当成新契约。对同一份样本比较预览和 Kafka 的业务字段，平台生成的 ID、接收时间与真实接入来源单独断言。回退先停止新版本生产，记录每个分区切换点，保留能读取已发布记录的消费者与表结构，演练重启后按原位移续读。自动化分层复用目录单测、真实组件集成测试和现有 Web 接入旅程。

**后续设计边界。** Event 提供稳定身份、版本和按引用回查的能力。correlator 服务、Alert 实体、表、API、界面及测试留待单独立项。本期发布与验收均可由现有四个应用、Kafka 和拟建的 CK 归档独立完成。

开发到运行的交付条件见[生命周期计划](../platform-architecture-review/plan.md#开发到运行的交付与交接)，维护入口见 [Ingest README](../../../src/apps/ingest/README.md#event-字段与存储设计)。
