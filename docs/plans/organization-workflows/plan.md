## 必测边界

1. 顶栏切换组织后，“当前组织”读取与保存都属于选中 ID；全部组织不错误继承该过滤。
2. 首次只取 10 条；滚动拉下一页；搜索重置 offset；旧搜索响应不会覆盖新搜索；选中项跨页/确认步骤后仍有正确名称；不允许提交纯搜索文字或禁用成员。
3. 名称允许中文，标识允许约定字符；最小/最大长度、31 字符、首尾符号、空白和重复标识前后端/DB一致。现存不合规数据明确阻止迁移，不静默修改。
4. 真实过期认证返回明确结果且业务未写入；切换密码步骤仍保留原组织名称、标识、已选管理员和原业务密码等 RHF 草稿。
5. 错误密码不丢稿不登出；正确确认后回原表单且不自动写入；用户再次提交仅执行一次。跨身份与跨组织边界、权限撤销、冲突和配置管理员保护仍成立。
6. 密码不进入请求调试输出、工具原始 Network 事件、日志或截图；只使用独立测试账号和数据库，不操作用户开发数据。

## 已批准的设计决定

采用 Spec 的整套建议：组织名称 1–30 字符并保留中文；标识 3–30 位并允许数字；保留现有两类高影响写操作的就地再次认证、默认窗口 30 分钟；取消独立确认身份入口。按批准方案更新默认窗口及就地流程。

实施中发现并修复两个必要集成点：近期确认不能将当前身份置为 unknown 而卸载页面；Base UI Combobox 的 Portal 需落入所属 Dialog 内，复用原生 container 能力，保持模板样式不变。测试 API fixture 在内存中复用管理员登录，不增加生产限额；认证过期 fixture 仅针对当前浏览器会话，不影响共享 API 会话。

完成证据、功能缺陷修复过程与隔离清理见 [验收记录](acceptance.md)。没有暂存、提交或推送。
