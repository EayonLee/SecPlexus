- 步骤都保留草稿。回到已完成步骤后，旧结果及时失效。通过可复用的步骤导航统一 `aria-current`、前后导航和焦点语义。现有接入向导需要的行为验证后再抽取共用部分。
- Combobox 默认先显示推荐和已选择字段，继续下拉或搜索可访问全目录。结果按用途分组，支持中文名、路径和同义词。选项展示区别同名字段所需的路径与适用范围，详情可查枚举。兼容多个类的全局映射可直接添加。局部不适用在预览解释，所选范围始终无法承载的映射在对应行修复。
- 搜索结果无匹配时保存用户已选值。样本切换同步更新提取值和归一化值，缺失、空值、隐藏和非法转换有不同状态。加载保留布局，接口错误保留草稿并提供当前步骤重试。焦点移动至首个问题，读屏可感知结果更新。
- 时间和严重度需要来源时从映射表进入对应专用控件。枚举转换贴在目标字段旁边。字段处理表单只出现对应参数和前后值。无需填写这些项的普通规则可从选字段直接验证。
- 规则单独初始化 `react-hook-form` 草稿。提取结果绑定格式、编码、处理项与样本指纹，完整结果额外绑定映射、分类和目录修订。修改后取消过期请求，迟到回包只在指纹仍匹配时应用。共享离开确认覆盖页面返回及取消。编辑保存继续携带预期修订，409 时保留本地稿件并提供重载比较入口。
- 目录查询由 TanStack Query 按版本和目录修订缓存，按安装实例和会话使用现有权限隔离。只读角色可查看已发布的规则及目录。处理表单按需加载，目录搜索以实际规模测量，可保持键盘行为的前提下再引入虚拟化。

数据接入继续使用「选择来源 → 连接配置 → 样本验证 → 确认创建」。套用模板会显示模板支持的日志及样本验证结果。复用规则向导同一试算入口和逐样本状态。连接页按协议显示字段及独立的厂商、产品；规则列表保持单表格，详情里的规则链接和权限沿用独立菜单。接入详情把启停、最近接收、成功／部分／未分类诊断分别显示，配置项采用共享字段布局。两个向导共用可证明一致的组件交互，各自保留对应的操作步骤。

## 3. 字段权威定义与类内约束

### 3.1 一份权威来源，两种生成视图

Ingest 在 `src/apps/ingest/schema/events` 管理权威定义。JSON 源文件和上游锁定信息随仓库评审，字段目录和校验索引随构建发布。PostgreSQL 保存规则引用的完整路径和转换配置。Web 提供只读目录和规则映射编辑。生成时从上游编译结果提取平台支持的字段、类型、基数、单位、对象路径、枚举和约束，再合入人工评审的中英文显示、搜索组及平台字段归属。用当前样本核验原有字段的业务含义、值域和校验结果，将审定后的公共字段和新增类别一起纳入 `v1`。

| 数据 | 唯一归属 | 示例 |
|---|---|---|
| 公共字段定义 | 以 OCSF 完整路径作为键。共同值域、类型和通用解释集中维护。显示分组是目录属性。 | `time`、`message`、`metadata.product.name`。平台生成字段带归属。 |
| 可复用对象 | 从上游对象及其引用生成，进入不同语义位置时保留各自路径。 | 源 IP 和目的 IP 都复用网络端点对象，分别为 `src_endpoint.ip` 和 `dst_endpoint.ip`。 |
| 每类适用性 | 按 `class_uid` 引用路径，维护必填、推荐、可选、条件及类内枚举。条件用可执行结构表示，带中英解释。 | 同一个 `activity_id` 在认证和网络类的动作定义各有作用域。相同数字仅在其所属类中解释。 |
| 映射目录 | 按完整路径去重，每项附适用类，搜索组与类目录并列生成。类视图从同一份产物还原。 | 「目的 IP」选择一次，详情可查看适用类别。区分所有类可用、部分支持类共享和类专属字段。 |

取上游编译结果中各类适用字段。Base Event 使用自己的字段集，多个具体类的交集只表示它们可以共用配置。若同路径的类型或基数在导入新类时冲突，生成报表并要求评审。仅在有明确上游依据时用类内元数据表达差异。通过编译产物生成结构化完整性规则，包括对象子字段、至少一个、恰好一个及枚举伴随字段。平台额外约束带来源、约束级别和例子。逐步将现有写死类 ID 的校验收敛到契约规则，测试验证正反样本覆盖原有语义。

### 3.2 字段范围与内置类型

当前目录、上游弃用情况和下一批来源模板见[事件类型命名与覆盖范围](../ingest-rule-field-workflow/plan.md#事件类型命名与覆盖范围)。

| 批次 | 场景 | 支持的 OCSF 类 | 样本与使用场景 |
|---|---|---|---|
| 首批 | 现有基础、身份和网络 | Base Event `0`、Authentication `3002`、Network Activity `4001` | 现有流量、登录成败、部分及未分类记录，补全共享字段和发布前后回归。 |
| 首批 | Web 与 DNS | HTTP Activity `4002`、DNS Activity `4003` | WAF／代理访问和 DNS 查询／响应。验证请求、响应和端点的字段用途。 |
| 首批 | 主机与端点 | File System Activity `1001`、Process Activity `1007` | 文件创建／删除、进程启动／结束。覆盖目标文件、进程和身份。 |

### 3.3 字段命名和枚举审核

从字段承载的对象、发生的动作和运营人员想查的信息出发，先读 OCSF 原定义，再核对国内安全运营文档及现有界面。特别审查事件与告警、日志来源与接入配置、账号与身份、操作结果与解析状态、网络处置与严重度。代码标识优先沿用 OCSF 路径和项目术语。平台自己的扩展字段、API、DTO、配置、文件和数据库名称按 `AGENTS.md` 的安全术语规范检查。字段审核清单记录原名、建议名、语义、来源、枚举与涉及的页面或投影。合并前覆盖全目录，以下是首轮样例。

| 路径或概念 | 拟定中文 | 使用说明 |
|---|---|---|
| `metadata.spx.input_id` | 接入点 ID | 对应「数据接入」中的一条接入配置，用于跳转和排查。厂商日志里的来源 ID 按实际来源另行命名。 |
| `metadata.uid` | 事件 ID | 当前归档事件的唯一编号。来源告警自己的 ID 依其字段语义展示。 |
| `src_endpoint.ip` / `dst_endpoint.ip` | 源 IP／目标 IP | 用于列表、映射和查询。按同一用词体系审查端口及端点。 |
| `status_id`（操作类活动） | 操作结果 | 标签用「成功」「失败」「未知」「其他」，沿用类内 OCSF 编码。登录详情可按动作展示「登录失败」。 |
| `metadata.spx["parse.outcome"]` | 解析状态 | 「解析成功」「部分解析」「解析失败」。预览另显示「未分类」类别；「登录失败」和「解析成功」可以同时出现。 |
| `class_uid` / `category_uid` / `type_uid` | 事件类别 ID／事件大类 ID／事件类型 ID | 用通俗名称描述不同层级。三个技术 ID 在详情按需展示。 |

- 枚举每个编码有一组中英短标签。中文源配置使用 `name` 和可选 `description` 的对象表达，生成目录的说明可以按语言省略。标签用于选择器和表格。确有附加含义时再展示释义，例如「其他」需要补充来源值的条件。
- 删除「操作失败」配「操作失败。」一类重复说明。生成检查对同语言标签与描述做空白、Unicode 标点归一比对，识别等义的表面复写。其余语义重复由评审判定。短标签结尾省略句号，完整说明正常用标点。中英文分别审核并保留示例。
- 公共枚举含义相同则复用符号和中英名称。类内含义不同就保留类内标签与适用范围。相同数字编码仅在所属枚举内解释。`成功／失败` 用于操作结果时，解析状态保持独立。导出和模型输入仍可查路径、值域和含义。
- 源文件和上游关注语义，推荐词、同义词及说明从目录流向 Web。给现有编码换一个更自然的中文显示名时同步文档和所需的物理注释，保留编码语义。展示术语若要同步到已应用的 ClickHouse 列注释，先冻结旧迁移生成输入，再通过前向迁移更新注释与实库预期。参见[事件存储设计](../event-contract/storage.md)。

## 4. 规则结构、试算与运行时

1. **提取。** 新增 `POST /api/v1/ingest/mappings/extract` 至现有映射路由组，使用 `ingest.mapping.write`、用户会话和 CSRF。请求携带解析设置、可选字段处理和样本。响应按输入顺序返回脱敏字段、可推定的原始值类型、派生结果、错误码和是否截断。此阶段可以没有完整规则及任何映射。输入复用现行 50 条、单条 64 KiB、请求体 4 MiB 限制。为返回字段数、单值长度和响应体设置上限，初始验收规格为每样本至多 128 条预览字段、单值预览 256 B、响应总量 512 KiB。截断显式标记。全规则试算沿用 `/mappings/validate`，补足分类证据、兼容字段、未落入标准正文的原因和脱敏后的 Event。
2. **有界处理。** 首批允许源值去除首尾空白、对字符串中的 JSON 提取命名字段。固定值属于映射。嵌入 JSON 复用现有解析器的安全行为，只提取明确配置的键，使用有序派生计划及独立输出路径。校验来源引用、相互覆盖、对象叶子冲突和依赖顺序。起始上限为每规则 8 个处理项，每段嵌套输入 16 KiB、深度 8、累计最多 64 个派生叶子。上限进入单测及基准，正式值以容量结果收敛。处理失败记录来源路径与原因并继续可独立进行的映射，原值不因处理而被覆盖。
3. **分类。** 模板用现有有序条件分支，自定义规则可不配置分类、确认单一类或配置多个分支。保留等于、属于集合和首条命中的语义。条件只读取原始已提取字段。禁止用样本字段的存在性推断事件含义。空分类配置编译成以 Base Event 为目标的通用规则。已配置的分支均未命中时走现有错误回退，并尽可能输出兼容的公共字段。规则配置阶段检查重复和可确定的遮蔽。
4. **归一化。** 新规则模型统一声明 `contract_version: "v1"`，移除试制期的 `definition_version: 2`。继续用已有的规则行修订处理并发和审计。规则内增加可选的共享映射与字段处理，编译保持单一入口。共享映射从全集选目标，按实际匹配类编译可写子集。类专属配置编译时校验目标、类型、值域，禁止同一输出路径被重复写入。类判定后，按类内枚举执行值转换，并由平台生成分类 ID 与元数据。时间默认用接收时间，使用转换来源和受控原因明确区分回退。事件只在契约通过后输出具体类。Base、部分和错误的判定见[规格](spec.md)。HTTP、Syslog、Kafka 及试算复用提取、分类和标准化逻辑。
5. **预览安全与审计。** 提取和完整试算在现有鉴权边界内运行，有明确的请求与 CPU 工作量上限。原始、派生、映射、最终 JSON 和诊断分别验证遮蔽策略，结构型数据递归处理，带敏感源的派生结果沿用敏感标记。设备原值和样本不得写入日志或管理审计。试算无事件发布、缓存刷新或持久化副作用。保存以 PostgreSQL 原有事务、规则版本及审计写入为边界。内置模板可提供发布样本，表单临时录入的样本留在会话内。

验收用同一份规则映射「事件消息」「目的 IP」「请求路径」（`http_request.url.path`）。流量、登录和 HTTP 访问按来源标识分别进入对应类，前两类保留各自适用的字段，HTTP 类还可输出请求路径。未提供来源标识的记录走 Base Event，事件消息依然输出。「目的 IP」或「请求路径」出现在样本里均不足以确定事件类别。用户若显式把「请求路径」限制到不支持该字段的单一类，系统在该映射行报告冲突。

运行时在配置刷新时编译不可变快照，失败保留上一次可用快照。每条报文按协议入流选择规则修订，解析一次，匹配和投影通过已编译路径和只读目录。热路径无数据库查询、跨服务目录查询及外部 I/O。大小、字段数或分支数耗尽时有确定的拒绝或诊断结果。分类、提取和最终归档状态使用稳定理由码，错误分辨规则冲突、样本问题和依赖异常。

## 5. 单一 v1、存储和多模块共享

首发只有一个平台 Event 契约，标识为 `v1`。标准字段仍以 OCSF 1.10.0 为上游；Event 使用 `metadata.version` 和 `metadata.spx.contract_version` 分别记录。字段目录产物统一为 `catalog.json`，内容摘要继续用于生成校验、构建对账和 HTTP 缓存。规则行修订仍用于并发控制、审计与定位，HTTP `/api/v1` 继续表达路由版本。新版本治理留待首发基线冻结后按实际变更设计。

| 参与方 | 获取方式 | 版本与责任 |
|---|---|---|
| Ingest 解析及归档 | 编译时嵌入唯一发布产物，启动加载和校验 | 按 `v1` 编译规则、验证事件和归档。未知契约走既有归档失败边界。 |
| Web | 保留目录、类详情，增加 `GET /event-schema/fields` 全字段视图 | 现有读权限。响应提供版本、摘要和适用性。各页面读取当前版本，复用按会话隔离的缓存。 |
| 下游检索、检测和模型数据准备 | 事件携带上游版本和平台契约标识，SDK、离线和其他语言共同消费生成的 JSON | 首个实际跨模块 Go 消费者出现时，再把只读产物和必要类型抽到 `src/packages/go`。目录维护继续由 Ingest 负责，产物通过可重复生成分发。 |
| ClickHouse | `event_json` 保存完整标准正文，物理投影沿用已发布列。 | 字段路径、类型、基数、投影值域和必需项在 CI 检查。投影 DDL 与实际表独立校验。跨新类缺失的可选投影应为空。 |

- **开发与迭代。** 首发前的修改集中进 `v1`，在代码评审展示路径、类型、单位、基数、枚举、约束和中文术语差异。CI 复生成并比对摘要，检查跨类定义、术语、投影和测试样本。首发后冻结发布产物。未来版本在明确消费者和变更范围后另定兼容窗口、迁移顺序与弃用日期。
- **安装与试制环境收敛。** 空库从固定发布产物和迁移启动，可断网运行。核对 Go 常量、生成器与嵌入文件、Web 请求及 Zod、种子模板、PostgreSQL JSONB `CHECK`、Kafka 消费、ClickHouse 投影和测试夹具。对已经应用 `00008` 的库，用前向迁移更新约束和重新登记内置模板。按确认的开发或独占测试环境范围，在停写后清理旧规则、旧修订及其接入绑定，重建新模板并检查引用。试制事件、积压和位移在确认范围内由独立运维步骤清理，或切换到干净的测试主题与归档库。安装迁移可重复执行，部署前验证事件契约与表结构。已执行的迁移保持原内容及校验和。
- **故障恢复。** 切换前登记目标、受影响的接入点、主题、消费组和位移，按目标环境要求保存配置快照。失败时保持入口停写并按整套构建及对应环境快照恢复；归档只运行当前版本。版本不可识别、摘要不符或表结构漂移按边界拒绝或停消费。按请求 ID、事件 ID、规则修订、契约版本、分区和位移排查。字段的业务含义从目录读取，ClickHouse 列类型、值域、默认和注释通过迁移及实库验证对齐。维持现有物理列、排序键、分区和 TTL；有实测查询需求的列另走迁移评审。
- **数据使用。** 告警与训练输入按目标类、契约版本和解析质量显式取数。归一化的字段、枚举释义和类适用性由生成产物提供，模型材料引用版本和摘要。由业务任务决定是否纳入部分解析样本。关联与模型调用归各自模块。
