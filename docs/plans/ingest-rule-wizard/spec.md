# 样本驱动的解析规则与统一字段目录

状态：已实施，核心流程已验收，持续容量待验证 · 2026-11-27

本规格记录现行向导。基础配置先选事件类型、按类型展示标准字段的后续方案见[类型驱动的向导规格](../ingest-rule-field-workflow/spec.md)。

## 用户流程

规则创建与编辑共用四步。用户先提供日志，再从标准字段目录选择目标。一个接入点、一条解析规则都可以覆盖多种日志。数据接入与解析规则保留独立菜单。

| 步骤 | 主要操作 | 进入下一步 |
|---|---|---|
| 基础配置 | 填规则名称、厂商、产品和可选描述，选择解析类型。键值对可填写字段分隔符、键值分隔符和引号。分隔符解析只填分隔符。「添加样本」在样本列表下方，标题处显示数量和 20 条上限。 | JSON 样本失焦时检查是否为单个合法 JSON 对象。「提取字段」先校验已填写的日志样本，再进入下一步。格式不符的提示显示在对应样本下方，焦点移到第一条失败的样本。 |
| 提取字段 | 左侧显示源字段、值和 JSON 类型标签，右侧显示只读日志样本。聚焦样本可切换左侧结果。分隔符解析按位置生成 `field_1`、`field_2` 等源字段。「高级设置」可选填非 UTF-8 来源的编码。文字字段可在窄抽屉处理，应用或移除后更新结果。 | 按当前提取结果进入字段映射。修改日志样本或解析类型时返回基础配置。来源编码只影响实际报文字节的读取。 |
| 字段映射 | 在此步骤添加映射。搜索覆盖平台已发布字段，组内将字段名称与路径同行展示。右侧沿用提取步骤的只读样本栏。 | 两行选择同一标准字段时，就地标记冲突并聚焦首项。「验证输出」对通过配置检查的规则执行试算。 |
| 预览保存 | 逐条检查事件类别、解析状态、归一化字段与原因，可展开 Event JSON。编辑时显示对使用该规则的数据接入的影响。 | 规则结构有效，当前样本已有验证结果。若用户有意保留未分类或部分解析样本，保存时列出影响并确认。 |

步骤标题在各自区域居中，整个可用步骤区域响应点击与键盘操作。点击下一步和底部操作执行同一套校验。接收端按 HTTP、Syslog、Kafka 各自边界识别报文。来源编码默认为 UTF-8，应用于实际收到的报文字节。粘贴的样本直接作为 UTF-8 文本提取和试算。[规则清理规格](../ingest-rule-cleanup/spec.md)

规则描述、正则表达式、日志样本的输入和只读展示，以及接入点的日志样本试算，共用三行文本框。长内容在框内滚动，高度固定。浏览器使用原生 JSON 解析和 Zod 对象校验。Ingest 使用实际解析器逐条提取，返回失败样本的位置。可正常提取但无法分类的日志样本仍可用于验证输出。

## 字段选择与分类

- **字段选择先于分类。** Combobox 按基础、来源、账号和身份、网络端点、进程和文件、Web 和 DNS、云与 API、安全发现等用途分组。中文名称、英文完整路径、释义和常用同义词可检索。样本中有高置信的同名字段时可推荐，搜索始终覆盖全集。用户可以选样本里暂无取值的目标、手动指定源路径或填写固定值。
- **同一路径只显示一次。** 例如「目的 IP」始终是 `dst_endpoint.ip`。路径的类型、基数和通用释义由目录维护，适用类分别声明是否支持、是否必填及可用枚举。应用于各类的 Base 公共映射只配一次。跨多个具体类的共享字段仅在支持它的类别中输出。
- **后台按日志语义分类。** 内置产品模板提供经样本验证的分类规则。通用规则默认可保存为 Base Event。需要输出具体类别时，在映射或预览中打开「事件分类」，可以声明来源本身的单一含义，或者将来源的明确标识值对应到多个事件类。例如把 `eventType` 的 `login` 对应到「认证活动」。类别名在需要时出现，平台生成 `class_uid`、`category_uid` 和 `type_uid`。样本或字段的偶然形状只可用于给出建议，不能自动确定类别。
- **平台契约决定可落库内容。** 同一份规则的网络记录和认证记录各自只产生一个 Event。运行时使用命中类的字段约束。无可靠语义时生成 Base Event，兼容的公共标准字段照常输出。若有字段无法进入当前类，允许保留的数据只能按既有策略进入受控 `unmapped`，并在样本上显示原因。候选类的必填项不足时，生成 Base Event 并标记部分解析，同时保留候选类和缺项。明确选择通用模式且产出有效 Base Event 时记「解析成功 · 未分类」。配置了分类而未命中、没有规则或无法提取的记录继续按已有错误语义归档。
- **常见字段处理就地出现。** 首批提供去除首尾空白、从嵌入 JSON 提取字段，另外可在映射行填固定值。时间解析、严重度和枚举转换按需在对应映射行配置。首批范围仅含这几种操作，样本字段表提供明确命名的「处理字段」入口。

例如，防火墙日志里的 `dst` 和登录日志里的 `target_ip` 都可映射到「目的 IP」。分类证据来自模板中的日志类别、消息标识和动作，或者用户确认的来源标识。某条日志只有 `dst` 时，页面可展示这项提取结果，归档仍依据实际类别约束。

## 平台标准和验收

- Ingest 维护 OCSF 1.10.0 基线，发布版本化的 SecPlexus 字段契约。发布目录包含英文路径、中英文名称和含义、JSON 与逻辑类型、单位、单值或数组、字段归属、适用类别、必填条件及枚举中英释义。字段搜索分组与 OCSF 类别是独立维度。
- 发布前统一为平台 Event 契约 `v1` 和一份生成目录。API 从当前目录读取版本，规则、数据面、归档和下游使用同一契约。旧试制规则和数据按确认的开发环境范围清理。后续真实版本升级由对应计划设计。
- 字段显示名按国内安全运营场景审定，并沿用英文路径、类型和枚举编码的标准语义。每个枚举有简短标签，只有补充取值含义、适用条件或排查线索时才提供释义。目录生成、接口和 Web 都接受省略重复释义。
- 内置目录覆盖身份、网络与 Web、主机端点、云审计及安全发现等常见业务场景，已发布类型均有公开或合成样本和验收。字段目录可用与产品模板可用分别展示。平台 Alert 和关联分析按独立计划交付。
- 普通规则可验证「贴样本、搜字段、保存」全程。混合日志的两个类别可用同一条规则预览、发布至 Kafka 并在 ClickHouse 回查。只有 Base Event 可用的日志仍能查询和解释。
- 目录、编译器、标准事件校验、ClickHouse 投影和下游消费使用同一发布契约。数据库投影有独立物理约束，发布和运行检查负责发现漂移。首次 v1 发布验证空库安装和试制环境清理后重建，归档按唯一受支持的版本校验。
- 界面在明暗主题、常用桌面及窄窗口下均可完成四步。支持键盘搜索与选择字段、转到首个问题、返回修改和并发冲突处理。样本变更后显示待验证，样本中未出现、值为空、被隐藏和转换失败有不同展示。临时输入样本随当前编辑会话持有，内置模板可使用已公开的样本。

实施细节、类范围、发布顺序和验收矩阵见[实施计划](plan.md)。
