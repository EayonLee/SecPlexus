# 方案审查与修订记录

本文记录实施前的方案评审；实施进度和实际验收以 [Plan](plan.md) 为准。

日期：2026-10-28。结论：上一版方向可用，但实施边界和验收不够完整；本次补充设计与计划，并按当前 AGENTS.md 收敛过度设计和重复验证；不代表产品代码已经实现，也不是对全仓代码的通过结论。

## 必须修正的缺口

| 编号 | 严重性 | 原计划缺口 | 风险与修订 |
|---|---|---|---|
| R1 | 高 | Result 的错误码示例与通用码规则不同，错误码清单与 OpenAPI 的权威关系不明确 | 前后端和后续语言会继续各写一套；统一注册表为事实来源，通用码不加模块，只有特有业务码加模块前缀，生成/校验产物不得反向定义协议 |
| R2 | 高 | ORM 验收列技术特性，但没有逐项列业务不变量 | 替换查询可能通过 CRUD 测试却破坏权限与会话；新增业务不变量矩阵、事务归属及并发验收，禁止用 ORM hook 替代授权 |
| R3 | 高 | 缺少中间件执行与失败顺序，未写响应提交条件 | 异常恢复、Session 提交、CSRF、SSE 和超时可能冲突；定义公开/内部/流式三条执行链，持久化或授权失败不能发送成功响应 |
| R4 | 高 | 先全量切换 Result，再验证 ORM；没有代表性完整链路的关卡 | 跨层设计未验证就扩大改动；改为先做用户或角色用例的完整切片，验证依赖、契约、连接池、事务后再推广 |
| R5 | 中 | 只有目录图，没有允许的 import、表归属与共享组件界限 | 改名后仍跨层访问；新增依赖表，模块私表不可跨服务读取，共享包不依赖应用实现，接口按调用方需要定义 |
| R6 | 中 | 启停、资源关闭、失败初始化和内部客户端没有统一生命周期规则 | 资源泄漏、重复连接池、服务未就绪或错误重试；明确创建/拥有/关闭关系和依赖失败行为，按服务实际需要装配 |
| R7 | 中 | 无标准化 HTTP 404/405、序列化错误、错误细节与重试约定 | 只有业务错误被包装，客户端仍遇到不一致；纳入 Result 边界和契约例外，禁止写操作无条件自动重试 |
| R8 | 中 | 前端只提统一解析，未明确组织切换、缓存和并发请求 | 旧组织数据或旧请求结果污染当前界面；补认证材料、组织维度查询键、失效/取消和错误交互约定 |
| R9 | 中 | 对可读性仅要求 gofmt、方法空行，缺少函数内部逻辑分段 | gofmt 不会替作者拆分逻辑；补有约束的可读性示例，工具检查格式，人审职责/命名/语义，不以固定行数代替判断 |
| R10 | 中 | 工程验证没有逐阶段产出与决定记录 | 设计结论与实际版本漂移；明确单一 Go module、锁文件、生成器、CI、独立模块运行和文档的验收产物 |
| R11 | 中 | skill 只列主题，没有规范定位和可复现审查流程 | 技能可能变成另一本长手册或擅自重构；补规范/实现状态标记、开发与审查边界、正反例和静态/运行证据要求 |
| R12 | 中 | 路由检查依赖源码中的 mux.HandleFunc 正则 | 改为路径分组后可能漏检或误判；纳入实际路由遍历、OpenAPI 对比和路径请求测试 |

## 按 AGENTS.md 收敛后的取舍

| 检查点 | 发现的问题 | 本次修改 |
|---|---|---|
| 单次边界校验 | 当前 contractValidation 与 httpx.Decode 都处理请求体；原计划只写“统一绑定”，未明确重复规则归属 | 请求入口拥有结构校验，内部传类型化值；业务授权、状态与事务检查继续保留 |
| 按需抽象 | 目录图、driver 字段和接口可能被机械实现成占位层 | 目录仅作职责示意；Console 简单调用不加 service；cache 保留现有字段，不做驱动框架；接口不以 Mock 为理由 |
| 推测性健壮性 | 原方案默认滚动升级和广泛故障/组合验证，尚无对应部署需求 | 本轮建议维护窗口升级；特殊 DDL 按实际迁移验证，新增极小概率边界须先说明收益与成本 |
| 可运行的实施顺序 | Result 全量切换与消费者更新分处不同阶段 | 试点先验证完整链路，再同批切换服务端与 Web/iamclient/脚本；后续按用例整理数据访问 |
| 最低必要测试 | 每阶段产物、全层矩阵和扫描规则叠加，可能维护成本大于收益 | 复用现有稳定套件，按测试层分配行为；关键并发与失败检查保留，不增通用故障平台/正则 linter |
| 技能维护 | 多处重复规范、完整样例矩阵可能演变为第二本手册 | 引用权威文档；用少量正常/违规样例核验开发与只读审查，不把目标当现状 |

上述调整是对当前方案的精简，不代表 chi/GORM 试点通过或任何产品验收已完成。必要的会话提交失败、审计原子性、管理员保护及跨实例撤销都有当前业务依据，仍保留验证。

## 本轮明确的范围

必须交付：当前 IAM/Console/Web 的契约、路由、数据访问、缓存命名、生命周期、错误/日志、配置、升级、代码可读性及验证；已有认证、授权和数据保护必须保持。

保留扩展边界：后续语言、后续服务、其他缓存和数据库驱动、新数据权限。先定义稳定边界，不建设不存在的服务、通用存储平台或策略引擎。

按需求另做：公网跨域部署、分布式追踪平台、消息总线/Outbox、跨服务事务、API Key/OIDC/MFA、自定义策略语言、大规模分页和全站前端视觉改造。本轮不能因为“架构完整”自动加入这些产品功能。

## 依据和判断方法

Gitea 已检出的路由、models/db 和 modelmigration 源码用于核对职责与升级；Grafana 的数据库与响应代码用于核对存储和响应边界。大型项目也有历史约束，不能把其每一层或全局状态视作规范。Go 模块布局说明 cmd/internal 的约定而非强制层数；GORM 文档明确事务、context 和错误处理能力，但是否保住本项目授权/会话不变量必须实测。
