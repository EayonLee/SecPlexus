## 五条设计原则

贯穿全部决策的原则，冲突时按此裁决：

1. **确定性的事交给代码，不确定的事交给 Agent**——分界线是"这一步能不能用字段精确描述"。
2. **Agent 负责想，SOAR 负责做**——AI 只调查不执行，处置必须人批（或按挣得的授权）。
3. **告警是事实，事件是视图，案件是对象**——兼容用户的告警运营习惯，AI 内部按事件组研判。
4. **每一次自动化都要有据可查**——"有文档的结论"而不是"无解释的关闭"。
5. **数据面质量先于 AI**——AI 再强也救不了喂进来的垃圾（Microsoft agent 被用户评 "mid" 的教训）。
6. **大脑的产出永久，输入只留工作窗口**——案件、调查记录、机构记忆永久；告警是用户系统的数据，只留 90 天工作记忆，考古跳回用户自己的 SIEM（存储即定位：我们不是第二档案馆）。
7. **正确性由机器保证，不靠人的记忆**——RLS policy 注册表自动建 + CI 断言、种子数据声明式同步、错误码集中注册、单语言共享包即单一事实源：一切"手动维护/人肉纪律"的方案不进入本系统。

- 【官方文档】厂商或标准的公开文档原文
- 【代码】直接读源码确认（本地仓库逐行核实）
- 【论文】arXiv / 会议论文的实测数据
- 【实测】真实运行/用户反馈（如 Reddit 一线评价）

- 【未核实】拿不到正文，明确不编造

## 产品姿态

SecPlexus 不是"又一个 SIEM"，也不是"又一个 SOAR"——它是**跨厂商告警之上的 AI 分析师层**：用户的 SIEM 继续做检测和日志，我们把多家的结论串成一个故事，交给 AI 分析师研判，人只做判断和授权。

展开成三句话：

1. **替换大脑，不造躯干。** 用户已经采购了各厂商的 SOC/EDR/WAF，没有必要再造一个又重又复杂的 SOC 去跟安全厂商竞争。AI 时代该做的是替换他们的"大脑"、指挥他们的"手脚"——研判结论落成处置动作，按上游原生 ID 回写，让已有的设备干活。
2. **第一价值主张是提效减负，不是更多功能。** 行业数据：SOC 平均每天收到约 3,000–4,500 条告警，**63–67% 无人调查**——告警量连年下降，被忽略的比例几乎没降【行业研究·Vectra AI 2023–2026】。用户的真实痛点是"上了 SOC 事情反而变多了、处理能力没提升"；我们的验收指标是分析师每天要看的告警数和工时，不是功能清单。
3. **跨厂商中立层是结构性差异。** 厂商自有 AI（Sentinel Copilot、Charlotte AI）被自家遥测边界锁住，异构栈里只有盲区；中立大脑坐在任何检测层之上，这正是"XDR 天花板"命题的解法。
